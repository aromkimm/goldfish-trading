# 판매 등록 에이전트 구현 계획과 검증

- 유형: 구현·검증. 상태: 로컬 구현·자동 시험·가상 예시 화면 검증 완료. 실제 상품·채널·효과 검증 미실행.
- 기준: [설계](../agents/product-listing/design.md), [등록 원칙](../docs/product-listing-principles.md).
- 목표: 대화형 조사·작성 흐름과 검색 근거를 연결한 등록 결과물 생성 도구를 구현한다.
- 구조: Python 표준 라이브러리의 `listing_agent/`가 v2 계약·검사·출력을 맡고, `workflow.md`가 에이전트의 조사·판단·작성 실행을 안내한다. 기존 `listing_tools/`와 예시는 보존하되 기본 진입점은 새 구현을 사용한다.
- 실행: 현재 작업 폴더의 미커밋 자료를 유지하는 `codex/listing-agent-v2` 브랜치에서 직접 구현한다. 별도 체크아웃으로 미커밋 설계를 누락하지 않는다. 계획 재승인 대신 사용자의 설계 기반 구현 지시를 적용한다.

## 가설

검색 판단·상품 사실·콘텐츠·채널 요구사항을 같은 버전으로 연결하면 근거 없는 등록 자료와 미완성 결과의 승인 오류를 줄일 수 있다. 판매 효과·시간 절감은 별도 검증이다.

## 검증 방법과 작업 순서

각 작업은 실패 테스트 → 구현 → 전체 `python3 -m unittest discover -s agents/product-listing/tests -v` 순서로 수행한다. 파일·출력 계약은 아래와 같으며 테스트는 실제 파일과 CLI를 사용한다.

- [x] 계약과 상태: `listing_agent/schema.py`, `tests/test_agent.py`. `validate(data, root) -> list[str]`, `readiness(data) -> dict`를 제공한다. 조사 환경, 수요 모름, 검색어 불일치, 경쟁 리뷰의 상품 사실 전용, 동적 채널 필수 필드, 근거 없는 문구, 충돌·권한·자리표시자를 검사한다. 자료 없는 정상 부분 초안은 구조 통과·게시 보류, 미확인 수요만 있는 완성 합성 사례는 검수 후 사람 검토 가능이어야 한다.
- [x] 준비·패키지 수명: `listing_agent/package.py`, `listing_agent/cli.py`, `tools.py`. `prepare`, `build`, `check`, `record_review`, `approve`를 제공한다. URL만 있는 브리프도 미조회 상태로 준비하며 외부 자료를 실행하지 않는다. 빌드는 새 디렉터리만 생성하고 검수·승인을 초기화한다. 변조·경로 이탈·출력 심볼릭 링크·다른 버전 승인은 실패해야 한다.
- [x] 출력: `listing_agent/render.py`. `render(data) -> dict[str,str]`가 등록 제안서·입력표·이미지 작업표·검수 보고·고객용 HTML·내부 미리보기를 생성한다. 구매 질문별 사진/제목/설명/표, 미완성 자산 표시, 고객용 내부 메모 제외, 이스케이프와 상대 이미지 경로를 시험한다.
- [x] 실행 절차와 검증: `workflow.md`, `README.md`, `contract.md`, `examples/format-demo/`, 전체 프로젝트 문서를 정합화한다. 합성 예시로 CLI 전체 흐름 및 PC·모바일을 검증한다. 실제 상품·판매자센터·사업 승인으로 표시하지 않는다.

중점 실패 조건: 선택하지 않은 이미지의 권한이 전체를 막지 않되 사용하는 이미지의 권한 누락은 차단; 동적 필드 목록의 필수값 누락; 수요 미확인을 영으로 바꾸기; 내용 변경 후 검수 재사용; 생성 파일 경로로 입력 파일을 덮어쓰기. 각 조건은 자동 테스트에 포함한다.

## 결과

- 확인된 것 — 2026-10-13 이 체크아웃의 Python 3.14.3에서 전체 자동 시험 41개 통과(새 계약 20개, 이전 회귀 21개). 신규 동작은 실패를 확인한 테스트 뒤 구현했다. 기존 예시·코드의 회귀 자료는 보존했다.
- 새 tools.py 기본 진입점, listing-2 계약, 동적 채널 필수 목록, 검색·경쟁 근거와 구매 질문 연결, 독립 상태 축, 자료 준비·버전·검수·승인, 결과물 생성 및 실행 문서를 구현했다. 검색·원문 읽기·의미 판단은 대화형 에이전트가 수행한다.
- 독립 코드 리뷰에서 미조회 권한/채널 출처의 확인 완료 허용과 과대한 정수 입력의 예외 전파를 재현했다. 각각 실패 테스트를 추가하고 수정 후 전체 통과를 확인했다.
- 가상 예시로 prepare → validate → build → check → review-template → review → check 흐름을 실행했다. 승인 성공/거부·버전 변경·변조 검사는 합성 테스트로 검증했으며 실제 상품 승인을 하지 않았다.
- 확인된 것 — 로컬 브라우저에서 예시 화면을 모바일 390×844, PC 1280×900 조건으로 확인했다. 이미지 로딩·가로 넘침 없음과 제목·설명·표 가독성을 확인했다. 예시는 직접 만든 도식과 가상 상품값을 사용하며 레퍼런스 내용·이미지를 복제하지 않았다. 실제 채널 검사는 미실행이다.
- 운영체제의 /var 임시 경로를 위험한 자료 링크로 오인하던 검사를 수정했다. 패키지 내부 자료·생성 대상의 심볼릭 링크와 경로 이탈 차단은 유지한다.
- 새 패키지의 고객용 HTML과 검토 화면을 분리했다. 미완성일 때 고객용 화면은 제공 불가 안내를 표시하고, 준비된 화면도 실제 게시 승인과 구분한다.
