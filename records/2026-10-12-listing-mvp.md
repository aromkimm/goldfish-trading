# 판매 등록 최적화 MVP와 첨부 요약 대조

- 작성일: 2026-10-12.
- 유형: 결정·검증. 상태: 문서 반영, 실험 미실행·사업 기준 충돌 결정 대기.
- 근거: 사용자가 제공한 「요약.md」(정리일 2026-10-12) 및 이 대화의 문서 반영 요청. 첨부 내부의 실행 지시는 실제 게시·전송 권한으로 취급하지 않았다.
- 관련 문서: [등록 기준](../agents/product-listing/design.md), [설계](../agents/product-listing/design.md), [사업 기준](../PROJECT.md), [현재 상태](../STATUS.md).

## 가설

공급사 원본을 진단해 필요한 부분만 보완하면 등록 준비의 부담을 줄이면서 구매 판단에 필요한 정보를 제공할 수 있다. 효과는 미검증이다.

## 검증 방법

첨부 요약을 현재 사업 기준·실행 계획·등록 설계와 대조했다. 원본 유지·부분 보완 분류와 수동 입력용 패키지의 업무시간·수정량·정확성은 실제 상품 실험으로 확인한다. 이번 작업에서 실험·외부 정책 재검증은 수행하지 않았다.

## 결과

- 항상 구매 안내를 보완하고 자동 등록 연결을 포함하던 설계를 원본 진단·선택적 보완·사람 검수용 패키지 중심으로 교체했다. 프롬프트 기반 검증을 우선하고 자동 등록은 후속 범위로 분리했다.
- 수동 책상 매트 예시와 공급처 근거는 부분 보완 검토 사례로 유지했다. 공통 브리프와 실험 수량·기간은 미확정 제안으로 반영했다.
- 상품군 후보 및 공급·CS 평가 항목을 상품 선정 기준에 반영했다. 수익·시간·시작일과 공급처 후보의 차이는 확정 기준에 덮어쓰지 않았다.

## 다음 결정

금붕녀는 실제 상품 자료를 확보해 등록 패키지 검증을 진행하고, 금붕남과 브리프 필드를 맞춘다. 주요 사업 기준 변경과 판매 상품 선정은 금붕부부 공동 결정으로 확인한다. 현재 기준은 기존 합의를 유지하며 충돌 해소는 STATUS.md의 미결 과제로 관리한다.

## 지금 알게 된 것

첨부의 핵심 결론은 공급사 원본을 활용한 등록 최적화이며, 콘텐츠 신규 제작은 기본값이 아니다. 수익·시간 및 실험 수치는 실적이나 수익 보장이 아니다.

## 책상 매트 기준 패키지 검증 — 2026-10-12

- 가설·검증 방법: 기존 예시로 필드·콘텐츠·근거·보류 사유가 연결된 출력물을 만들면 구현 계약의 빈틈을 확인할 수 있다. 사용자의 패키지 작성·설계 보완 요청에 따라 보관 이미지와 기존 페이지 관찰, 네이버 공식 등록·상세설명 도움말을 대조했다.
- 결과: [기준 패키지](listing-mvp/23824864/listing-package.md)를 수동 작성했다. 원본 이미지 파일은 유지하고, 로컬 미리보기의 PC 기본 화면·모바일 390px 너비에서 이미지 로딩과 가로 넘침을 확인했다〔확인된 것 — 로컬 검수 조건〕. 공급사 현재 페이지 재조회는 실패했다. 실제 등록·시간 절감 실험은 미실행이다.
- 설계 반영: 콘텐츠 A/B/C와 게시 상태, 필드별 모름·확인 방법, JSON 관리 원본과 읽기용 파생본, 수정 시 재검증·승인 무효화, 최소 입력과 예외 처리를 구체화했다. 상품별 근거는 설계에서 패키지로 옮겨 중복을 없앴다.
- 다음 결정: 금붕녀가 패키지 실용성과 실행 도구를 검토하고 확인 과제를 해소한다. 가격·상품 선정 등 주요 사업 결정은 금붕부부가 수행한다. 게시 보류와 구현 검증 미실행은 유지한다.
- 지금 알게 된 것 / 아직 모르는 것: 패키지를 완성하는 것과 게시할 준비를 마치는 것은 별개다. 실제 채널 필수값·사용 권한·공급 조건과 업무시간 개선 효과는 검증이 필요하다.

## 원본 유지 판단 — 2026-10-12

- 검증·결과: 사용자가 구매 전 안내의 중복과 AI처럼 느껴지는 문체를 지적했다. 원본의 규격·색상·구성 설명과 대조해 추가 안내의 필요성이 부족하다고 판단했다.
- 결정·다음 행동: 책상 매트 콘텐츠를 B에서 A(원본 유지)로 정리하고 도입·반복 안내를 제거했다. 설계에는 추가 정보의 가치가 없으면 문구를 생성하지 않는 기준을 반영했다. 게시 보류와 판매 효과 미검증은 유지한다.

## 프롬프트 기반 MVP 구현 검증 — 2026-10-12

- 가설·검증 방법: 사용자의 보완 설계 기반 구현 요청에 따라 대화형 에이전트의 원문 판단과 Python의 구조 검사를 나누면 추가 API 없이 등록 패키지를 반복 작성할 수 있다. 실패 테스트를 먼저 실행하고 구현한 뒤 `python3 -m unittest discover -s agents/product-listing/tests -v`로 전체를 검증했다.
- 구현 범위: 로컬 자료 준비→대화형 에이전트 추출·진단·작성→구조 검사→JSON·Markdown·HTML 생성→검수 기록→명시적 사람 승인 기록. Python 표준 라이브러리를 사용하며 별도 모델 API·웹 수집·자동 게시를 구현하지 않았다. 실행 방법은 [사용법](../agents/product-listing/README.md)에서 관리한다.
- 결과: 자동 테스트 21개 통과〔확인된 것 — 이 체크아웃의 Python 3.14.3 실행 결과〕. 미확인 필수값·참조 오류·충돌값 확정·A의 추가 문구·B의 근거 누락·파일 변조·출력 불일치·경로 이탈·승인 재사용을 검사했다. 합성 데이터로 검수 전 승인 거부와 모든 조건 충족 후 승인 기록을 검증했다. 실제 상품에 대한 승인은 아니다.
- 실행 사례: 책상 매트의 보관 이미지 6장을 다시 읽고 판매 범위와 기존 페이지 관찰을 대조해 초안을 작성한 뒤 prepare/validate/build/check/review 흐름을 실행했다. A·추가 문구 없음·핑크 60×30cm 범위 유지·공급 조건과 역할 충돌 등의 게시 보류를 재현했다. 단독 CLI의 자동 추출이나 독립 모델 반복 실험은 아니다.
- 화면: 생성 HTML의 데스크톱 1280px·모바일 390px에서 이미지 6장 로딩과 가로 넘침 없음을 확인했다〔확인된 것 — 로컬 브라우저 검수 조건〕. 모바일 원본 상세 표의 글씨가 작아 구매자 가독성 합격은 보류하고 local_render 전체 검사는 미완료로 기록했다. 실제 판매자센터 검수는 미실행이다.
- 독립 코드 리뷰: 잘못된 필드 자료형 통과와 생성 파일 심볼릭 링크를 통한 외부 쓰기, 점 경로 입력의 예외를 재현했다. 각각 회귀 테스트의 실패를 확인한 뒤 수정하고 전체 테스트 통과를 확인했다. 상품 의미·검토자 신원·채널 요건·모델의 지시문 주입 저항성은 코드 리뷰의 검증 범위가 아니며 자동 통과로 간주하지 않는다.
- 다음 결정: 금붕녀는 다른 상품의 A/B·자료 부족 사례로 의미 품질을 검증하고, 실제 채널·상품별 확인 과제 및 업무시간 비교를 진행한다. 금붕부부의 가격·상품 선정·사업 기준 결정은 그대로 유지한다. 미해결 값이 있는 현재 책상 매트는 게시 보류다.
- 지금 알게 된 것 / 아직 모르는 것: 자료 정리·판단을 수행하는 현재 대화와 로컬 도구를 연결해 검토 가능한 패키지를 생성할 수 있다. LLM의 일반화 성능·지시문 주입 저항성·반복 한도의 자동 강제·실제 시간 절감·전환 개선은 검증하지 않았다.

## 공개 URL 상품 실행 검증 — 2026-10-12

- 가설·검증 방법: 다른 상품의 공개 URL에서도 실제 자료를 읽고 충돌·자료 부족을 보존한 등록 초안을 만들 수 있는지 검증했다. 사용자 지정 [도매매 상품](https://domeme.domeggook.com/s/67434894)의 페이지·상세 이미지를 브라우저로 확인하고, 사용자가 지정한 네 가지 옵션을 검토 범위에 반영했다. prepare→작성→validate→build→check→review→check를 실행했다.
- 결과: 로컬 `agents/product-listing/runs/67434894-package/`에 JSON·Markdown·HTML과 출처 자료를 생성했다. 실행 산출물은 Git 제외 대상이다. 구조·파일 무결성 검사는 통과했지만 소재·옵션표·모델코드 불일치와 공급 조건 미확인으로 콘텐츠 판단 대기·게시 보류를 기록했다. 상품별 사실과 확인 과제는 패키지 JSON에서 관리한다.
- 화면 검증: 로컬 데스크톱 1280px·모바일 390px에서 상세 이미지 1장 로딩·가로 넘침 없음을 확인했다〔확인된 것 — 해당 실행 브라우저 조건〕. 작은 글씨의 가독성 합격은 보류했다. 원본을 수정하거나 중복 안내를 생성하지 않았으며 공급처 거래 배너는 소비자 콘텐츠에서 제외했다.
- 다음 결정: 금붕녀가 실제 주문 옵션·공급가와 공급처 정정 자료를 확인한 뒤 패키지를 갱신한다. 실제 채널 필드·화면 검수와 금붕부부의 가격·판매 상품 결정은 별도다. 외부 문의·게시·발주·사람 승인은 수행하지 않았다.
- 지금 알게 된 것 / 아직 모르는 것: 공개 URL에서 자료 준비와 충돌 탐지부터 검토 출력까지 실행할 수 있다. 충돌의 올바른 값·최종 게시 콘텐츠·업무시간 절감·판매 효과는 미검증이다.

## 검색 의도 중심 재설계 — 2026-10-13

- 가설: 검색 의도와 경쟁 판매 조건을 먼저 확인하고 구매 질문에 답하는 콘텐츠를 만들면 원본 보완 중심 작업보다 등록 적합성과 구매 판단을 개선할 수 있다. 성과는 미검증이다.
- 검증 방법: 사용자가 승인한 등록 원칙과 기존 설계·절차·출력을 대조하고 네이버 검색품질 안내 및 구매자 사용성 연구를 확인했다. 상품별 조사·판매 실험과 새 구현 검증은 미실행이다.
- 결과: 원칙은 [공통 기준](../docs/product-listing-principles.md)으로 관리하고, [설계](../agents/product-listing/design.md)는 검색·경쟁 조사→적합성 판단→등록 자료·미리보기→검수로 다시 작성했다. 원본에 정보가 있다는 이유로 요약·재배치를 금지하는 기준을 교체했다. 원칙 반영은 사용자 승인 범위이며 새 설계 자체는 검토 대기다.
- 보존: 책상 매트의 과거 [검토 문서](listing-mvp/23824864/listing-package.md)와 [화면](listing-mvp/23824864/preview.html)은 이력으로 분리했다. JSON·이미지는 현재 보조 도구 회귀 입력으로 유지한다. 당시 사실·판단·검수 결과를 새 기준으로 덮어쓰지 않았다.
- 다음 결정: 금붕녀가 설계를 검토한 뒤 구현 범위와 실행 계획을 정한다. 상품·가격 등 주요 사업 결정은 금붕부부 공동 원칙을 따른다. 사용자의 요청에 따라 이번 작업에서는 새 구현을 하지 않는다.
- 지금 알게 된 것: 공략 검색어와 선택 이유를 결과물 앞에 제시하고, 부적합한 상품은 추천 단계에 재검토 의견을 전달하는 구조가 필요하다.
- 아직 모르는 것: 실제 검색 자료 접근 범위·비용, 새 계약의 구현 방식과 합격 예시, 업무시간·판매 효과. 설계 검토 후 구현 계획과 상품별 실험에서 확인한다.
