# 상품 선정 에이전트 착수 및 선정 기준 결정

- 작성일: 2026-10-10.
- 유형: 결정. 상태: 결정 반영 완료, API 확인·구현 미실행.
- 근거: 이 대화에서 사용자가 전달한 금붕부부 결정.
- 관련 기준 문서: [상품 선정 기준](../docs/product-selection.md), [상품 선정 에이전트](../docs/product-selection-agent.md), [실행 계획](../docs/execution-plan.md).

## 가설

같은 도매 상품을 여러 판매자가 동시에 파는 위탁판매에서는, 수요가 있으면서 동일 상품 판매자가 적은 상품을 골라야 경쟁력이 생긴다.

## 검증 방법

미실행. 에이전트 구현 후 표본으로 포화도 측정 정확도를 확인하고, 등록 상품의 노출·주문 결과와 대조한다.

## 결과

- 에이전트 개발 시점: 기존 원칙(수동 검증 후 개발)을 상품 선정 에이전트에는 적용하지 않고 지금 개발한다. 사용자 근거: 수익률보다 실행에 의의를 두며, 위탁판매 손실은 시간뿐이고 여가시간으로 충당한다.
- 에이전트 이견: 무재고여도 반품 배송비·품절 취소 페널티·도매 선결제 자금·수수료 등 금전 손실 가능성이 있어 "손실은 시간뿐"은 검증되지 않은 전제다. 비용 확인과 예산·손실 한도는 기존 미결 과제로 유지했다.
- 적용 범위: 위 결정은 상품 선정 에이전트에 한정해 반영했다. 품절·단가 동기화와 등록 자동화는 기존 착수 조건을 유지한다.
- 판매가: 최저가·경쟁 중앙가를 모두 시도한 뒤 전략을 정한다.
- 초기 제외 상품군: 기존 기준안을 그대로 확정 적용하고 판매 경험 후 재정비한다.
- 동일 상품 포화도를 핵심 지표로 추가했다.
- 데이터 API 공식 문서 확인 시도(2026-10-10): 네이버 개발자센터·검색광고 API 문서는 조회 실패, 도매매 API 문서는 검색되지 않음. 모든 API 조건은 모름.

## 다음 결정

- 결정 주체: 금붕부부 공동. 구현·API 계정 발급 담당은 미배정.
- 후속 행동: API 접근 조건 확인 → 구현 → 후보 비교표 산출 → 금붕부부 선정.
- 대기: 포화도·검색량·경쟁 밀도 임계값, 가중치, 판매가 전략, 구현 담당.

## 지금 알게 된 것

상품 선정 에이전트의 착수 시점, 판매가 비교 방식, 제외 기준, 핵심 지표, 운영 방식(승인 후 등록), 베타 조건(20개·8주·수동 업로드·방치 기본·최소 개입)이 정해졌다.

## 아직 모르는 것

데이터 API의 접근 가능 여부와 조건, 포화도 측정 정확도, 지표와 실제 판매의 관계.

## 운영 방식 결정 — 2026-10-10

- 결정(사용자가 전달한 금붕부부 결정): 자동화 수준은 승인 후 자동(금붕부부 승인 상품만 등록, 정리도 승인). 소수 상품 베타 운영 후 상품 수·확장 전략을 정한다. 근거: 상품 수가 늘면 리스크와 관리 지점이 함께 늘어난다.
- 리뉴얼은 결정이 아니라 논의 대상이다. 개선·정리 방식 후보와 판정 기준은 에이전트 제안값으로 [운영 방식](../docs/product-selection-agent.md#운영-방식)에 반영했고 결정 대기다.
- 에이전트 이견: 승인 후 자동 업로드에는 등록 자동화 개발이 필요해 기존 후속 자동화 순서와 겹친다. 베타는 수동 업로드를 추천하며 업로드 방식은 미결로 두었다. 20개 규모로는 가격 전략 우열을 판정할 수 없어 베타 목적을 운영 흐름·판정 기준 확인으로 제안했다.
- 반영: 에이전트 설계(운영 방식), 실행 계획(수동 등록 → 베타 운영, 확장 전 조건), STATUS 미결 과제.

## 베타 조건 확정 — 2026-10-10

- 결정(사용자가 전달한 금붕부부 결정): 베타 20개·8주, 승인 상품 수동 업로드.
- 정정: 판정 기준과 리뉴얼 방식은 결정 요청이 아니라 선택지·추천 질의였다. 등록 후 관리 전략 전체(방치·개선·교체·승자 확장·휴면·삭제 후 재등록)로 넓혀 다시 제안했고, 직전 제안의 "1회 개선 후 4주 재관찰"은 판매 원인 해석을 흐린다는 이유로 "방치 기본·4주차 노출 없음만 수정·8주차 유지 또는 교체"로 대체했다. 결정 대기.
- 후속 결정: 베타는 방치 기본·최소 개입(상시 품절·마진·정책 조치, 4주차 노출 없음 상품 수정)으로 운영하고 8주 후 관리 전략을 재정비한다. 결정 주체: 금붕부부 공동.

## 개발 착수 — 2026-10-10

- 결정: 사용자가 에이전트 개발 착수를 지시했다(금붕부부 결정 전달). 구현은 에이전트가 수행한다.
- API 확인 결과: 네이버 개발자센터는 도구 접근이 차단돼 네이버 공식 GitHub 문서(naver-openapi-guide 2026-10-06 갱신, searchad-apidoc)와 도매꾹 Open API 문서로 확인했다. 확인 내용은 [에이전트 설계](../docs/product-selection-agent.md#데이터-출처). 도매꾹·검색광고 호출 한도와 검색광고 라이선스의 광고비 요건은 모름.
- 새로 알게 된 제약: 도매처 최저판매준수가격이 있으면 최저가 시나리오의 하한이 된다. 상세페이지 이미지 사용 허용 여부가 상품별로 다르다.
- 결과: 1차 코드와 오프라인 테스트 14건 통과. 실호출 검증·포화도 정확도 검증·데이터랩 연동은 미실행.
- 다음: 금붕부부의 API 키 발급(계정 생성·키 입력은 에이전트가 대신하지 않음) → 실호출 검증.

## 쇼핑 검색 API 미제공 확인 — 2026-10-10

- 발견: 사용자가 개발자센터 앱 등록 화면에서 검색·데이터랩 API가 선택 목록에 없음을 확인했다. NAVER API HUB 공식 제공 목록에도 쇼핑 검색이 없다. 제3자 자료는 2026-07-31 대체 없이 종료, 검색·데이터랩은 API HUB로 이관이라고 전한다(네이버 공지 원문 미확인).
- 에이전트 오류: 앞선 API 확인에서 개편 전 내용이 남은 네이버 GitHub 문서를 최신으로 판단했다. 공식 문서 갱신일만으로 현행 여부를 단정하지 않고, 제공 목록·공지를 함께 확인한다.
- 영향: 경쟁 밀도·경쟁가·동일 상품 포화도 수집이 불가. 대체 방안은 결정 대기.
- 결정(사용자가 전달한 금붕부부 결정): 크롤링은 하지 않는다(약관·차단 위험, 판매 채널 리스크). 경쟁 밀도·경쟁가·동일 상품 포화도는 상위 후보를 사람이 확인하고, 에이전트가 확인 화면과 반영을 맡는다. 도매꾹 대체 신호를 함께 기록해 베타 후 자동화 가능성을 판단한다. 이미지 웹 검색 서비스(Google Cloud Vision) 시험은 계정·결제 수단이 필요해 보류.
- 근거로 확인한 것: shopping.naver.com/robots.txt가 일반 크롤러 전면 차단(2026-10-10). 네이버 약관의 자동 수집 금지는 2차 자료로만 확인.
- 반영: 이미지 비교 코드 제거, 수동 확인 화면·반영 기능 추가, 오프라인 테스트 16건 통과.
- 검색광고 API 실호출(2026-10-10): 비즈머니 미충전 계정에서 라이선스 발급·키워드 도구 호출 성공. 검색수는 문서와 달리 숫자형으로 왔다. 사용자가 비밀키가 보이는 화면을 공유해 재발급을 권고했고, 재발급 값은 `.env`에만 입력됐다.
- 도매꾹 API 실호출(2026-10-10): 목록·상세 성공. 실제 배송비가 대부분 수량별비례로 와서, 문서 규칙대로 1개 주문 기준 배송비를 계산하도록 수정했다(이전에는 모름 처리).

## 판매 가능 조건 확인 추가 — 2026-10-10

- 요구(사용자가 전달): 추천 후 등록 전에 옵션·공급가, 품절·출고·주문 마감, 배송비·추가배송비·묶음배송, 교환·반품, 이미지 사용 범위, 인증·표시·판매 제한을 확보하고, 조건 불충족·정보 미확보면 선정 단계로 돌려보낸다.
- 실호출로 알게 된 것: 도매 상세페이지는 이미지뿐이라 주문 마감 시간·반품 접수 방법은 API로 얻을 수 없다. 무료배송 판매 시 반품비가 2배 적용되는 상품이 있다. 도매 판매기간 종료일이 1개월 안팎으로 잡힌 상품이 흔해 반려가 아닌 주의로 둔다. 도매꾹 Open API 엔드포인트는 2026-08-12부터 www 주소로 바뀌어 반영했다.
- 반영: API 자동 확보 + 사람 확인 화면 + 판매 조건서. 반려 기준은 제안값으로 결정 대기. 오프라인 테스트 21건 통과.

## 범위 재정의 — 2026-10-10

- 전달 내용: 사용자는 다른 팀원과 역할을 나눠, 사용자는 상품 추천 에이전트만 맡고 상품 관리·운영 전략은 다른 팀원이 개발한다. 에이전트 범위는 ① API로 데이터를 모아 잘 팔릴 만한 상품 추천 ② 추천 상품의 판매 가능 조건 확인 두 가지로 정의한다.
- 영향: 이 기록 앞부분의 운영 관련 결정(승인 후 등록 방식, 베타 20개·8주·수동 업로드, 방치·최소 개입·8주 후 재정비, 판매가 전략 시도, 개선·정리 선택지)은 사용자 범위 밖이었으므로 현재 문서에서 제거했다. 운영 담당이 참고할 논의 이력으로만 남는다.
- 반영: 에이전트 설계 문서를 두 기능 범위로 정리하고 실행 계획·STATUS·스킬에서 운영 항목을 운영 담당 영역으로 넘겼다. 담당자 이름은 확인 대기.
- 후속 전달(2026-10-10): 추천 담당은 금붕남, 운영 담당은 금붕녀. 판매 가능 조건의 반려 기준은 전달 문구 그대로(배송·반품 조건 불일치 또는 정보 미확보)로 하고, 에이전트가 제안했던 출고 2일 초과·이미지 불허 반려는 주의 표시로 낮췄다. 첫 후보 검색 범위는 에이전트 제안을 요청받았다.

## 완전 자동화·외부 마켓 데이터 전환 — 2026-10-10

- 첫 실행: 6개 키워드(욕실선반·벽선반·틈새선반·리빙박스·폴딩박스·무릎담요, 에이전트 제안을 금붕남이 채택)로 도매매 163건 수집 → 규칙 제외 10, triage 제외 1 → 152건 검색량 수집 → 수동 확인 화면 30건 생성(대표 키워드당 3개 상한).
- 결정(사용자 전달): 수동 입력 부담이 커서 받아들이지 않는다. 목표는 완전 자동화이며, 판매 플랫폼이 네이버여도 분석 데이터는 네이버에 한정하지 않는다.
- 재확인: 네이버 공지 32530·32564 원문으로 쇼핑 검색 API 종료(2026-07-31, 대체 없음, 기존 키 포함)를 확인했다. 도매꾹 가격비교 값은 후보 152개 중 4개에만 있어 대체 불가.
- 채택안: 경쟁·가격은 11번가 상품검색, 추세·관심도는 NAVER API HUB(쇼핑 인사이트·블로그 검색), 쿠팡 파트너스는 판매 실적 승인 후 추가. 11번가 포화도가 네이버를 반영한다는 가설은 10개 안팎 표본으로 1회 검증한다. 북마클릿 반자동안과 스크래핑 대행 서비스안은 채택하지 않았다.

## 11번가 경쟁 수집 실행 — 2026-10-10

- 가설 시험(표본 12건): 대표 키워드로 11번가를 검색하면 상위 200개 안에서 같은 상품을 3건만 찾았다. 도매 상품명으로 검색하면 10건에서 같은 상품 판매자 2~61명을 찾았다. 그래서 상품명 검색을 채택했다.
- 실행 결과(후보 152개, 실패 0, 약 6분): 같은 상품 판매자 0명 13개, 1~5명 31개, 6~20명 52개, 21명 이상 56개. 경쟁가가 같은 상품 기준인 후보 123개.
- 마진〔추정치 — 무료배송 가정, 수수료 차감 전〕: 같은 상품 최저가로 팔면 152개 중 94개가 적자, 중앙가로 팔면 20개가 적자. 11번가의 같은 상품 리뷰는 13개 후보에만 있었고 최대 14건이라 판매 흔적 신호로는 약하다.
- 아직 모르는 것: 11번가 포화도가 네이버와 맞는지, 11번가 하루 호출 한도.
