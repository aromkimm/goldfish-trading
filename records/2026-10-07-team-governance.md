# 호칭 및 공동 결정 원칙 수정

- 작성일: 2026-10-07.
- 유형: 결정. 상태: 완료.
- 근거: 금붕녀가 이 대화에서 요청한 호칭 변경과 공동 의사결정 원칙 정정.
- 이전 기록: [문서 분리 전 기준](2026-10-07-baseline.md).

## 가설

기존 문서가 금붕녀를 단독 사업 결정권자로 표현해 실제 협업 구조와 맞지 않는다.

## 검증 방법

사용자 정정 내용과 현재 문서의 호칭·결정 주체를 대조한다.

## 결과

현재 문서의 호칭은 금붕녀·금붕남, 공동 주체는 금붕부부로 변경했다. 과거 기록은 당시 표기를 보존하고 정정 내용을 연결했다.

## 다음 결정

주요 사업 결정은 금붕부부가 함께 하고, 위임된 실무 결정은 담당자가 수행한다. 결정 주체와 실행 담당자를 구분해 기록한다.
반영 문서: [작업 지침](../AGENTS.md), [사업 기준](../PROJECT.md), [현재 상태](../STATUS.md), [상품 기준](../docs/product-selection.md), [기록 양식](TEMPLATE.md), [문서 안내](../README.md).

## 지금 알게 된 것

대화 참여자와 단독 결정권자는 동일하지 않으며, 주요 사업 결정은 공동으로 관리한다.

## 아직 모르는 것

개인별 실무 위임 범위와 역할 분담은 미정이다.

## 실행 역할 배정 — 2026-10-10

- 근거·결과: 사용자가 상품 후보 조사·비교 영역을 “판매 상품 에이전트”를 만드는 기능 단위로 나누고 금붕남이 진행한다고 전달했다. 구축·실측 검증은 미보고다.
- 반영: STATUS.md의 실행 담당을 금붕남으로 지정하고, 실행 계획에서 이 작업은 첫 주문을 기다리지 않고 진행하도록 정합화했다. 그 외 운영 자동화의 착수 조건은 유지한다.
- 다음 결정: 상세 기능·완료 조건 및 다른 업무의 담당은 미정이다. 주요 사업 기준과 상품 선정은 기존 금붕부부 공동 결정 원칙을 따른다.

## 독립 개발 방향 — 2026-10-10 후속 결정

- 가설·검증 방법: 에이전트 간 연결을 먼저 설계해야 하는지에 대해 사용자 지시와 기존 실행 조건을 대조했다. 기능·운영 검증은 미실행이다.
- 결과: 금붕남의 판매 상품 에이전트와 금붕녀의 스토어 운영 에이전트를 연결 없이 각각 설계·구현하는 방향으로 진행한다. 첫 주문 이후로 운영 개발을 유보하던 조건과 순차 파이프라인 일정 초안은 현재 계획에서 교체했다. 기존 초안은 [기준 기록](2026-10-07-baseline.md)에 보존돼 있다.
- 다음 결정: 실행 담당은 각 에이전트를 진행하며 주요 사업 결정은 금붕부부 공동으로 유지한다. 에이전트가 제안한 스프린트 목표는 사용자 확정 전이므로 실행 계획에 목표안으로 구분한다.
- 지금 알게 된 것 / 아직 모르는 것: 독립 설계·구현 방향은 확인됐으나 스프린트 기간·상세 기능·완료 기준·자동 실행 권한은 미정이다. 초기 버전 구현 완료나 설계만 수행하는 범위 어느 쪽도 확정하지 않았다.

## 개설 담당과 개발 실무 범위 — 2026-10-10 후속 결정

- 가설·검증 방법: 다음 행동을 준비·설계 과제로 나누는 것이 담당자의 실행 범위와 맞는지 사용자 지시와 대조했다.
- 결과: 개인판매자 스토어는 금붕녀가 실제로 개설한다. 첫 사용 사례·입출력·구현 범위·검증 기준 정하기는 각 담당자의 에이전트 만들기에 포함한다. 별도 선행 과제와 스프린트 목표안은 현재 문서에서 제거했다.
- 다음 결정: 각 담당자가 에이전트 만들기를 진행하고 금붕녀가 스토어를 개설한다. 주요 사업 결정은 금붕부부 공동 원칙을 따른다.
- 지금 알게 된 것 / 아직 모르는 것: 개설 담당과 개발 실무 범위는 확인됐다. 실제 개설·구현 결과는 미보고이며, 후속 행정 담당과 실제 자동 실행 권한은 미정이다.
