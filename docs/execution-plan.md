# 금붕상사 실행 계획

실행 순서와 착수 조건을 관리한다. 현재 진행 상태와 담당자는 [STATUS.md](../STATUS.md)에 기록한다.

## 진행 순서

시장·고객 가설 → 데이터 검증 → 상품 평가 → 마케팅·운영 설계 → 제한된 실행 → 성과 검토.

각 단계 시작 전에 완료 조건과 검증 기준을 정한다. 기준 변경 및 검증 전 실행 결정은 사유·실험 한도·중단 조건과 함께 기록한다.

## 자동화 및 실행 초안

- 상품 선정 에이전트는 판매 검증을 기다리지 않고 지금 개발한다. 수익률보다 실행을 우선하는 금붕부부 결정에 따른다. 설계는 [상품 선정 에이전트](product-selection-agent.md)를 따른다.
- 그 외 자동화는 베타 운영으로 업무를 파악한 뒤 확인된 병목부터 개발한다. 우선순위: 품절·단가 동기화 → 등록 자동화. 등록은 기존 무료 도구의 기능·비용·연동 범위를 검증한 뒤 활용한다.
- 경쟁 가격 모니터링은 추가 후보로 둔다. 데이터 수집 전 API 접근 권한·약관·제한을 확인한다.
- 아래 일정은 `추정치 — 미확정 실행 초안`이다. 베타 운영의 20개·8주는 금붕부부 확정 계획값이다. 착수일과 완료 기한은 미정이다.

| 단계 | 기간 초안 | 작업 |
| --- | --- | --- |
| 상품 선정 에이전트 | 미정 | API 접근 조건 확인 → 구현 → 후보 비교표 산출 |
| 행정 준비 | 1~2주 | 정한 명의에 맞는 사업자·스토어·통신판매 관련 요건 확인 및 준비 → 도매처 가입·API 접근 준비 |
| 베타 운영 | 8주 | 승인한 20개 상품을 수동 업로드해 운영 흐름과 판매 원인 확인. 관리 전략은 [운영 방식](product-selection-agent.md#운영-방식) 참조 |
| 후속 자동화 | 4주 | 확인된 병목에 한정해 구현. 일정 경과만으로 자동 착수하지 않는다. |

- 사업자 명의는 [사업 기준](../PROJECT.md#사업-개요)을 따른다. 과세 유형·업종·신고 의무는 확정 전이며, 적용 세율·기한·면제 요건은 공식 자료로 확인한다.
- 사업용 통장·카드 분리를 검토하고, 정산 전 도매 결제에 필요한 자금도 확인한다. 무재고를 무비용으로 해석하지 않는다.

## 착수 조건

- 상품 후보 조사: 현재 합의된 사업 기준으로 착수한다. 행정 준비와 세부 운영 조건의 미결 사항은 조사 착수를 막지 않는다. 후보 평가에는 도매 결제 자금·배송·반품을 포함한 비용 구조를 반영한다.
- 상품 선정 에이전트 구현 전: 사용할 API의 접근 조건·약관·호출 한도 확인.
- 행정 신청 전: 정한 명의에 맞는 최신 행정 요건 확인.
- 지출 전: 실제 필요 비용을 확인하고 금붕부부가 예산·손실 한도를 판단한다.
- 판매 개시 전: 행정 준비, 상품 평가, 가격·배송·반품 처리 방법, 도매 결제 자금과 예산 확인. 판매 관찰 시작 기준도 정한다.
- 후속 자동화 개발 착수 전: 병목의 작업 시간·발생 빈도와 기존 도구의 대체 가능성 확인. 첫 주문 조건과 일정의 해석은 미결 과제로 유지.
- 베타 이후 확장 전: 베타 결과로 관리 전략과 상품 수·확장 전략을 금붕부부가 재정비한다.
