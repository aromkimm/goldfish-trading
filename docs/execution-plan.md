# 금붕상사 실행 계획

[사업 목표](../PROJECT.md#목적과-목표)를 실행 단계와 착수 조건으로 연결한다. 현재 진행 상태·담당·미결 과제는 [STATUS.md](../STATUS.md)에서 관리한다.

## 실행 흐름

추천·등록 에이전트는 독립적으로 개발하며 실제 상품으로 검증한다. [Phase 1 목표](../PROJECT.md#목적과-목표)의 실행 결과는 검수·판매 준비를 거쳐 실제로 등록한 상품이다. 도구 구현이나 시안 제작만으로 이 목표를 달성한 것으로 판단하지 않는다. 판매 성과와 운영 부담은 등록 후 관찰해 장기 자동화 목표의 실현 가능성을 판단한다.

| 단계 | 해야 할 일 | 다음 단계에 필요한 결과 |
| --- | --- | --- |
| 후보 조사·추천 | [선정 기준](product-selection.md)에 따라 수요·적합성·경쟁·공급·비용·운영 부담 비교 | 추천 근거와 반대 근거, 상품 정보·공급 조건·미확인 사항 및 [판매 조건서](product-selection-agent.md#판매-가능-조건-확인) |
| 상품 선정 | 금붕부부가 추천 근거와 불확실성을 검토 | 등록 검토할 상품과 판매 범위 |
| 등록 자료 작성 | 검색·경쟁 조건 구체화, 적합성 판단, 필드·사진 포함 상세 시안 작성 | [등록 결과물](../agents/product-listing/README.md#사용하기)과 확인 과제. 부적합 발견 시 선정 단계로 재검토 의견 전달 |
| 게시 판단·수동 등록 | 상품별 검수와 아래 판매 착수 조건 확인 | 해당 버전의 게시 판단과 실제 등록 결과 |
| 판매 운영·성과 관찰 | 주문·발주·배송·CS·취소·교환·반품·정산을 처리하며 판매·손익·수동 개입 관찰 | 판매 가설의 결과와 반복 업무·예외 처리 부담 |
| 다음 판단 | [검토 시점과 평가 기준](../PROJECT.md#검토-시점)에 따라 관측 근거 검토 | 금붕부부의 계속·방향 전환·중단 판단과 상품·업무 개선 범위 |

판매 이후 업무는 초기 에이전트 개발 범위에서 제외하지만 실제 주문 처리는 필요하다. 판매 개시 전 사람이 처리할 방법과 담당을 정한다. 행정·자금 준비도 별도로 진행하며, 미배정 업무는 [현재 상태](../STATUS.md#미결-과제)에서 관리한다.

## 에이전트 개발 방향

| 구분 | 책임·범위 |
| --- | --- |
| 추천 에이전트 | [후보 조사·비교·추천과 판매 가능 조건 확인](product-selection-agent.md). 상품 정보·공급 조건·근거를 판매 조건서로 전달 |
| 등록 에이전트 | 선택된 상품의 검색·경쟁 조건을 구체화하고 등록 자료·상세 시안 작성·검수. 부적합 발견 시 추천 단계에 재검토 의견 전달 |
| 정보 전달 | 초기에는 수동 전달. [상품 브리프](../agents/product-listing/README.md#상품-브리프)를 참고하되 공통 API·데이터 형식 합의와 에이전트 간 연동은 개발 선행 조건으로 두지 않음 |
| 개발 실무 | 각 담당자가 첫 사용 사례·입출력·구현 범위·검증 기준을 정하고 설계·구현·검증. 기존 도구의 기능·비용·제한도 확인 |
| 후속 개발 | 주문·발주·배송·CS·정산 등 판매 이후 업무는 Phase 1 개발 범위 밖. 실제 수요와 업무를 확인한 뒤 필요성 판단 |
| 사람의 준비 업무 | 행정·자금 준비와 준비 완료 여부 확인 기능은 에이전트 범위 밖 |

등록 업무의 입력과 책임 범위는 [사용법](../agents/product-listing/README.md), 실행·검증은 [작업 절차](../agents/product-listing/workflow.md)를 따른다.

## 소규모 검증 흐름

사업 전체의 관찰 기간은 [사업 기준](../PROJECT.md#사업-개요)을 따른다. 아래는 상품별 실험을 구체화하기 위한 **미확정 제안값**이다. 수량·기간은 사용자 제공 [첨부 요약의 반영 내용](../records/2026-10-12-listing-mvp.md)을 따른다. 산정 근거와 적정성은 미검증이며 측정 결과나 합의된 목표가 아니다.

| 항목 | 제안값·적용 조건 |
| --- | --- |
| 첫 실험 규모 | 후보 약 10개 → 약 3개 선정 → 1~3개 등록〔추정치〕 |
| 후속 규모 | 첫 실험 결과를 바탕으로 10~20개 시험 등록과 3~5개 주력 상품 집중 검토〔추정치〕 |
| 상품별 관찰 기간 | 등록 후 2~4주〔추정치〕. 사업 전체 관찰 기간을 대체하지 않음 |

실험 전에는 검증할 판매 가설, 판매 범위·가격, 관찰 기간·기산점, 확보할 지표와 기록 담당을 정한다. 실험 수량·기간과 사업 기준의 미결 사항은 [STATUS.md](../STATUS.md#미결-과제)에서 관리한다.

| 검증 대상 | 자료와 다음 판단 |
| --- | --- |
| 등록 업무의 효과 | [에이전트 검증 계획](../agents/product-listing/workflow.md#검증-계획)에 따라 같은 범위의 수동 작업과 시간·품질을 비교해 도구 개선 여부 판단 |
| 판매 가설 | 확보 가능한 검색 유입·노출·클릭·주문을 같은 기간·상품 범위·분모로 비교. [손익·운영 지표](../PROJECT.md#운영-및-평가)와 함께 상품·가격·정보 개선 여부 판단 |
| 자동화 필요성 | 반복 업무와 수동 개입 원인·시간을 바탕으로 자동화할 업무 검토. 등록 API와 판매 이후 업무는 필요성 확인 후 개발 범위 판단 |

확보하지 못한 지표는 모름으로 두고, 노출 부족 상태에서 전환 효과를 단정하지 않는다. 전후 변화만으로 콘텐츠·태그의 인과 효과를 확정하지 않는다. 재검증·결정에 필요한 결과는 [기록 양식](../records/TEMPLATE.md)에 남기며, 실제 자동 실행은 아래 착수 조건을 충족한 뒤 진행한다.

## 스마트스토어 개설·사업자등록·통신판매업 신고

- 성격: 실행 권고안. 과세유형·업종의 최종 확정 및 실제 신청과 구분.
- 개인판매자와 전환할 사업자 대표자의 명의는 [사업 기준](../PROJECT.md#사업-개요)에 맞춰 동일하게 유지한다.
- 현재 전제: [사업·판매 이력](../STATUS.md#현재-단계) 기준 신규 진입. 당근 거래는 개인 사용 물품 처분이라는 전제.

| 시점 | 업무 | 처리 기준 |
| --- | --- | --- |
| 판매 준비 시 | 운영·행정 정보 확인 | 선정 상품의 공급사 조건에 맞춘 스토어 설정, 상호·사업장 주소 확인. 담당별 현재 행동은 [STATUS.md](../STATUS.md#다음-행동) 참조 |
| 판매 상품 확정 후, 판매 개시 전 | 사업자등록 | 홈택스 개인사업자 신청. 간이과세 적용 가능 여부·업종 확인 후 신청 |
| 사업자등록증 발급 후 | 스토어 사업자 전환 | 판매자정보 → 사업자 전환 → 사업자번호·필수 서류 제출. 도매매 사업자 인증 병행 |
| 사업자 전환 시 | 통신판매업 신고 판단 | 간이사업자·면제 조건 충족 시 신고 보류. 일반과세자 전환 시 네이버 제출 요건에 따른 신고 진행 |
| 전환·발주 준비 완료 후 | 판매 개시 | [판매 착수 조건](#착수-조건) 충족 후 상품 판매 상태 전환 |

### 적용 근거와 예외

아래 공식 요건은 `확인된 것 — 2026-10-10 공식 안내 확인` 기준. 개별 적용 판단은 전제·권고와 구분.

- 개설·전환: 사업자등록 전 개인판매자 개설 및 등록 후 동일 대표자 사업자 전환 가능. [네이버 가입 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=15949), [전환 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3759).
- 법정 신청 기한: 사업 개시일부터 **20일 이내 사업자등록 신청**. 첫 판매 전 등록 완료의 일률적 의무와 구분. [국세청](https://j.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7776&mi=2443).
- 판매 전 등록 권고 근거: 도매매 사업자 전용 상품 구매의 사업자 인증 요건. 첫 주문 후 등록 시 발주 지연 가능성. 구매확정·정산 입금까지 등록을 미루는 방식 제외. [도매꾹·도매매 안내](https://help.domeggook.com/ko/articles/사업자-인증은-어떻게-하나요-0cc88c1b).
- 법정 신고 면제: **직전년도 통신판매 거래횟수 50회 미만 또는 간이과세자** 중 하나 충족 시 통신판매업 신고 면제. 청약철회 등은 거래횟수 산입 제외. 현재 전제상 거래횟수 조건 충족 판단. 사업자등록 의무와 별개. [공정위 고시 제2조](https://www.law.go.kr/admRulInfoP.do?admRulSeq=2100000210384).
- 네이버 전환 요건: 간이사업자 신고번호 입력 미필수, 일반 개인사업자·법인 필수. 신고 필요 시 **사업자 전환 신청의 ‘미신고’ 선택 → 구매안전서비스 이용확인증 발급 → 정부24 통신판매업 신고 → 신고번호 반영**. [네이버 전환 절차](https://help.sell.smartstore.naver.com/faq/content.help?faqId=15766).
- 신고 재검토: 과세유형 변경·면제 조건 이탈·네이버 신고번호 제출 요구 발생 시 확인. 네이버의 개인판매자·일반사업자 기준에 **당해년도 누적 구매확정 50건 이상** 포함. 법령의 직전년도 거래횟수 기준과 구분. [네이버 제출 기준](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3681).

## 착수 조건

| 행동 | 먼저 확인할 조건 |
| --- | --- |
| 상품 후보 조사 | 행정·세부 운영 미결 사항과 별개로 착수. 후보별 공급·배송·반품 조건과 정산 전 도매 결제 자금을 포함한 비용 구조 검토 |
| 에이전트 설계·구현 | 첫 주문을 기다리지 않음. 데이터·도구 사용 전 접근 권한·약관·제한 확인 |
| 행정 신청 | [행정 절차](#스마트스토어-개설사업자등록통신판매업-신고)의 개별 적용 조건·최신 제출 요건 확인 |
| 지출 | 실제 필요 비용 확인 후 금붕부부가 예산·손실 한도 판단 |
| 판매 개시 | 행정 준비·상품 평가·가격·판매 운영의 처리 방법과 담당·도매 결제 자금·예산 확인 및 관찰 시작 기준 확정. 사업용 통장·카드 분리 검토 |
| 실제 자동 실행 | 대상 업무의 정상·예외 처리, 실패 감지·수동 대응 검증. 실행 권한과 사람의 승인 범위 확정 |

등록 자료의 게시 검토 조건은 [상태와 게시 판단](../agents/product-listing/data-contract.md#상태와-게시-판단)을 함께 적용한다.
