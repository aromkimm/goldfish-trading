# 금붕상사 실행 계획

실행 순서와 착수 조건을 관리한다. 현재 진행 상태와 담당자는 [STATUS.md](../STATUS.md)에 기록한다.

## 에이전트 개발 방향

- 추천·등록 에이전트를 독립적으로 설계·구현한다. 초기 정보 전달은 수동으로 하며 에이전트 간 연동이나 공통 API·데이터 형식을 선행 조건으로 두지 않는다.
- 추천 에이전트는 후보 조사·비교·추천과 최초 판매 적합성 검증을 수행하고, 상품 정보·공급 조건·근거를 전달한다. 전달 항목은 [상품 브리프 초안](../agents/product-listing/design.md#상품-브리프)을 참고하며 공통 필드 확정은 개발 선행 조건으로 두지 않는다.
- 등록 전략·상세페이지 품질은 [상품 등록 원칙](product-listing-principles.md), 입력·처리·출력 계약은 [등록 설계](../agents/product-listing/design.md)에서 관리한다. 등록 에이전트는 선택된 상품의 검색·경쟁 조건을 구체화하고, 부적합 발견 시 추천 단계에 재검토 의견을 전달한다. 실행 방법은 [등록 작업 절차](../agents/product-listing/workflow.md)를 따른다.
- 주문·발주·배송·CS·정산 등 판매 이후 업무는 Phase 1 개발 범위에서 제외한다. 실제 수요와 업무를 확인한 뒤 개발 필요성을 판단한다.
- 행정·자금 준비는 사람이 수행한다. 준비 업무와 준비 완료 여부 확인 기능은 에이전트 범위에 포함하지 않는다.
- 각 담당자는 첫 사용 사례·입출력·구현 범위·검증 기준을 정하고 개발한다. 기존 도구의 기능·비용·제한을 확인하며, 담당과 진행 상태는 [STATUS.md](../STATUS.md#다음-행동)를 따른다.

## 소규모 검증 흐름

추천 → 금붕부부의 상품 선정 → 검색 의도·경쟁 조건 조사와 상품 적합성 확인 → 등록 자료 작성·검수 → 사람의 게시 판단·수동 등록 → 성과 관찰 순으로 검증한다. 등록 조사에서 부적합이 발견되면 상품 선정 단계로 재검토 의견을 돌려준다. 등록 에이전트의 실험 방식과 품질 평가는 [설계](../agents/product-listing/design.md#검증-계획)를 따른다.

- 첫 실험 제안: 후보 약 10개 → 약 3개 선정 → 1~3개 등록. 이후 10~20개 시험 등록과 3~5개 주력 상품 집중을 검토한다. 모두 추정치 — 첨부 요약의 미확정 제안 수량이며 실적·할당 목표가 아니다.
- 등록 후 2~4주 관찰은 추정치 — 첨부 요약의 실험 기간 제안이다. 사업 전체의 [관찰 기간](../PROJECT.md#사업-개요)을 대체하지 않는다. 노출·클릭·주문과 [운영·손익 지표](../PROJECT.md#운영-및-평가)를 확인하며 노출 부족 시 콘텐츠의 전환 효과를 단정하지 않는다.
- 반복 업무와 성과가 확인된 뒤 자동화 확대를 검토한다. 등록 API와 판매 이후 업무 개발은 필요성과 실행 권한 검증을 거친다.

## 스마트스토어 개설·사업자등록·통신판매업 신고

- 성격: 실행 권고안. 과세유형·업종의 최종 확정 및 실제 신청과 구분.
- 개인판매자와 전환할 사업자 대표자의 명의는 [사업 기준](../PROJECT.md#사업-개요)에 맞춰 동일하게 유지한다.
- 현재 전제: [사업·판매 이력](../STATUS.md#현재-단계) 기준 신규 진입. 당근 거래는 개인 사용 물품 처분이라는 전제.

| 시점 | 업무 | 처리 기준 |
| --- | --- | --- |
| 판매 준비 시 | 운영·행정 정보 확인 | 선정 상품의 공급사 조건에 맞춘 스토어 설정, 상호·사업장 주소 확인. 담당별 현재 행동은 [STATUS.md](../STATUS.md#다음-행동) 참조 |
| 판매 상품 확정 후, 판매 개시 전 | 사업자등록 | 홈택스 개인사업자 신청. 간이과세 적용 가능 여부·업종 확인 후 신청 |
| 사업자등록증 발급 후 | 스토어 사업자 전환 | 판매자정보 → 사업자 전환 → 사업자번호·필수 서류 제출. 도매매 사업자 인증 병행 |
| 사업자 전환 시 | 통신판매업 신고 판단 | 간이사업자·면제 조건 충족 시 신고 보류. 일반과세자 전환 시 네이버 제출 요건에 따른 신고 진행 |
| 전환·발주 준비 완료 후 | 판매 개시 | 아래 착수 조건 충족 후 상품 판매 상태 전환 |

### 적용 근거와 예외

아래 공식 요건은 `확인된 것 — 2026-10-10 공식 안내 확인` 기준. 개별 적용 판단은 전제·권고와 구분.

- 개설·전환: 사업자등록 전 개인판매자 개설 및 등록 후 동일 대표자 사업자 전환 가능. [네이버 가입 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=15949), [전환 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3759).
- 법정 신청 기한: 사업 개시일부터 **20일 이내 사업자등록 신청**. 첫 판매 전 등록 완료의 일률적 의무와 구분. [국세청](https://j.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7776&mi=2443).
- 판매 전 등록 권고 근거: 도매매 사업자 전용 상품 구매의 사업자 인증 요건. 첫 주문 후 등록 시 발주 지연 가능성. 구매확정·정산 입금까지 등록을 미루는 방식 제외. [도매꾹·도매매 안내](https://help.domeggook.com/ko/articles/사업자-인증은-어떻게-하나요-0cc88c1b).
- 법정 신고 면제: **직전년도 통신판매 거래횟수 50회 미만 또는 간이과세자** 중 하나 충족 시 통신판매업 신고 면제. 청약철회 등은 거래횟수 산입 제외. 현재 전제상 거래횟수 조건 충족 판단. 사업자등록 의무와 별개. [공정위 고시 제2조](https://www.law.go.kr/admRulInfoP.do?admRulSeq=2100000210384).
- 네이버 전환 요건: 간이사업자 신고번호 입력 미필수, 일반 개인사업자·법인 필수. 신고 필요 시 **사업자 전환 신청의 ‘미신고’ 선택 → 구매안전서비스 이용확인증 발급 → 정부24 통신판매업 신고 → 신고번호 반영**. [네이버 전환 절차](https://help.sell.smartstore.naver.com/faq/content.help?faqId=15766).
- 신고 재검토: 과세유형 변경·면제 조건 이탈·네이버 신고번호 제출 요구 발생 시 확인. 네이버의 개인판매자·일반사업자 기준에 **당해년도 누적 구매확정 50건 이상** 포함. 법령의 직전년도 거래횟수 기준과 구분. [네이버 제출 기준](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3681).

## 착수 조건

- 상품 후보 조사: 행정 준비·세부 운영 조건의 미결 사항과 별개로 착수한다. 후보별 공급·배송·반품 조건과 정산 전 도매 결제 자금을 포함한 비용 구조를 검토한다.
- 행정 신청 전: 위 개설·등록 절차에 따른 적용 조건 및 최신 제출 요건 확인.
- 지출 전: 실제 필요 비용을 확인하고 금붕부부가 예산·손실 한도를 판단한다.
- 판매 개시 전: 행정 준비, 상품 평가, 가격·배송·반품 처리 방법, 도매 결제 자금과 예산을 확인하고 관찰 시작 기준을 정한다. 사업용 통장·카드 분리를 검토한다.
- 에이전트 설계·구현: 첫 주문을 선행 조건으로 두지 않는다. 데이터·도구 사용 전 접근 권한·약관·제한을 확인한다.
- 실제 자동 실행 전: 대상 업무의 정상·예외 처리와 실패 감지·수동 대응을 검증하고, 실행 권한과 사람의 승인 범위를 정한다.
