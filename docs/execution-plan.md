# 금붕상사 실행 계획

실행 순서와 착수 조건을 관리한다. 현재 진행 상태와 담당자는 [STATUS.md](../STATUS.md)에 기록한다.

## 진행 순서

시장·고객 가설 → 데이터 검증 → 상품 평가 → 마케팅·운영 설계 → 제한된 실행 → 성과 검토.

각 단계 시작 전에 완료 조건과 검증 기준을 정한다. 기준 변경 및 검증 전 실행 결정은 사유·실험 한도·중단 조건과 함께 기록한다.

## 에이전트 개발 방향

- 판매 상품 에이전트와 스토어 운영 에이전트를 각각 독립적으로 설계·구현한다. 초기에는 에이전트 간 연동을 구현하지 않는다. 필요한 정보는 수동 전달하며 공통 API·데이터 형식은 선행 조건으로 두지 않는다.
- 판매 상품 에이전트는 후보 조사·비교·추천, 스토어 운영 에이전트는 판매 운영 업무 지원을 대상으로 한다. 첫 사용 사례·입출력·상세 기능·우선순위·구현 범위·검증 기준은 에이전트 만들기에 포함하여 각 담당자가 정한다. 담당과 진행 상태는 [STATUS.md](../STATUS.md#다음-행동)에서 관리한다.
- 기존 도구의 기능·비용·제한을 확인해 개발 범위를 정한다. 설계·구현과 실제 판매·자동 실행 개시는 구분하며, 적용 조건은 아래 착수 조건을 따른다.

## 운영 준비

- 사업용 통장·카드 분리를 검토하고, 정산 전 도매 결제에 필요한 자금도 확인한다. 무재고를 무비용으로 해석하지 않는다.

## 스마트스토어 개설·사업자등록·통신판매업 신고

- 성격: 실행 권고안. 과세유형·업종의 최종 확정 및 실제 신청과 구분.
- 명의: [사업 기준](../PROJECT.md#사업-개요) 적용. 개인판매자와 전환할 사업자 대표자의 동일 명의 유지.
- 현재 전제: [사업·판매 이력](../STATUS.md#현재-단계) 기준 신규 진입. 당근 거래는 개인 사용 물품 처분이라는 전제.

| 시점 | 업무 | 처리 기준 |
| --- | --- | --- |
| 현재 | 개인판매자 스토어 개설 | 대표자 네이버 아이디로 커머스 ID 생성 → 개인판매자 가입 → 본인인증·정산계좌·스토어 정보 입력 |
| 개설 후 | 판매 준비 | 상품·공급처 선정, 스토어 설정, 상호·사업장 주소·공급처 구매 조건 확인 |
| 상품·공급처 확정 후, 판매 개시 전 | 사업자등록 | 홈택스 개인사업자 신청. 간이과세 적용 가능 여부·업종 확인 후 신청 |
| 사업자등록증 발급 후 | 스토어 사업자 전환 | 판매자정보 → 사업자 전환 → 사업자번호·필수 서류 제출. 도매매 사업자 인증 병행 |
| 사업자 전환 시 | 통신판매업 신고 판단 | 간이사업자·면제 조건 충족 시 신고 보류. 일반과세자 전환 시 네이버 제출 요건에 따른 신고 진행 |
| 전환·발주 준비 완료 후 | 판매 개시 | 아래 착수 조건 충족 후 상품 판매 상태 전환 |

### 적용 근거와 예외

아래 공식 요건은 `확인된 것 — 2026-10-10 공식 안내 확인` 기준. 개별 적용 판단은 전제·권고와 구분.

- 개설·전환: 사업자등록 전 개인판매자 개설 및 등록 후 동일 대표자 사업자 전환 가능. [네이버 가입 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=15949), [전환 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3759).
- 법정 신청 기한: 사업 개시일부터 **20일 이내 사업자등록 신청**. 첫 판매 전 등록 완료의 일률적 의무와 구분. [국세청](https://j.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7776&mi=2443).
- 판매 전 등록 권고 근거: 도매매 사업자 전용 상품 구매의 사업자 인증 요건. 첫 주문 후 등록 시 발주 지연 가능성. 구매확정·정산 입금까지 등록을 미루는 방식 제외. [도매꾹·도매매 안내](https://help.domeggook.com/ko/articles/사업자-인증은-어떻게-하나요-0cc88c1b).
- 법정 신고 면제: **직전년도 통신판매 거래횟수 50회 미만 또는 간이과세자** 중 하나 충족 시 통신판매업 신고 면제. 청약철회 등은 거래횟수 산입 제외. 현재 전제상 거래횟수 조건 충족 판단. 사업자등록 의무와 별개. [공정위 고시 제2조](https://www.law.go.kr/admRulInfoP.do?admRulSeq=2100000210384).
- 네이버 전환 요건: 간이사업자 신고번호 입력 미필수, 일반 개인사업자·법인 필수. 신고 필요 시 **사업자 전환 신청의 ‘미신고’ 선택 → 구매안전서비스 이용확인증 발급 → 정부24 통신판매업 신고 → 신고번호 반영**. [네이버 전환 절차](https://help.sell.smartstore.naver.com/faq/content.help?faqId=15766).
- 신고 재검토: 과세유형 변경·면제 조건 이탈·네이버 신고번호 제출 요구 발생 시 확인. 네이버의 개인판매자·일반사업자 기준에 **당해년도 누적 구매확정 50건 이상** 포함. 법령의 직전년도 거래횟수 기준과 구분. [네이버 제출 기준](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3681).
- 미결 항목: [현재 상태](../STATUS.md#미결-과제)에서 관리. 홈택스 신청 요건 및 관할기관 안내로 실행 전 확인 필요.

## 착수 조건

- 상품 후보 조사: 현재 합의된 사업 기준으로 착수한다. 행정 준비와 세부 운영 조건의 미결 사항은 조사 착수를 막지 않는다. 후보 평가에는 도매 결제 자금·배송·반품을 포함한 비용 구조를 반영한다.
- 행정 신청 전: 위 개설·등록 절차에 따른 적용 조건 및 최신 제출 요건 확인.
- 지출 전: 실제 필요 비용을 확인하고 금붕부부가 예산·손실 한도를 판단한다.
- 판매 개시 전: 행정 준비, 상품 평가, 가격·배송·반품 처리 방법, 도매 결제 자금과 예산 확인. 판매 관찰 시작 기준도 정한다.
- 에이전트 설계·구현: 첫 주문을 선행 조건으로 두지 않는다. 데이터·도구 사용 전 접근 권한·약관·제한을 확인한다.
- 실제 자동 실행 전: 대상 업무의 정상·예외 처리와 실패 감지·수동 대응을 검증하고, 실행 권한과 사람의 승인 범위를 정한다.
