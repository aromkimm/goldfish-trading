# 금붕상사 실행 계획

[사업 목표](../PROJECT.md#목적과-목표)를 실행·검증·다음 판단으로 연결한다. 현재 진행 상태·담당은 [STATUS.md](../STATUS.md), 평가 항목과 계산은 [선정 기준](product-selection.md)에서 관리한다.

## 실행 순서

| 단계 | 실행 | 다음 판단에 필요한 결과 |
| --- | --- | --- |
| 1. 공급처 거래 자격 | 한국 거주 개인/사업자의 가입·결제·발주와 요구 서류·현지 거점 조건을 공식 자료·직접 답변으로 확인 | 한국 계정으로 실제 거래 가능한 조건. 단순 가입 성공·한국 배송 지원과 구분 |
| 2. 출고·반품 운영 | 선매입 없는 1개 주문, 판매자 표시, 대상 시장 판매 허용, 발송·추적·반품 주소·비용·환불 방식 확인 | 공급처 전체 조건과 상품별 예외, 우리 처리 업무·필요 플랜 |
| 3. 상품과 실제 비용 | 조건을 충족한 공급처에서 SKU·구성·재고·품질 자료·공급가·목적지별 배송 견적 확보 | 금붕상사 계정에 적용되는 주문 원가와 견적 조건 |
| 4. 경쟁·수요·손익 | Amazon 비교 상품과 공급 후보를 대조하고 기여이익·월 고정비·반품 민감도 계산 | 고객이 선택할 이유, 가격 근거, 손익분기 조건, 미확인 비용 |
| 5. 최소 주문 시험 | 금붕부부가 비용·범위를 정한 경우 결제·포장·송장·배송·품질을 실제 확인 | 플랫폼 설명과 실제 이행의 차이. 미실행이면 시험 완료로 표현하지 않음 |
| 6. 판매 준비·시작 | 계정·정산·행정·상품 권한·등록 자료·운영 담당과 예외 처리 확인 후 판매 | 상품 URL·판매 상태·시작일 및 관찰 기준 |
| 7. 성과 검토 | 실주문·취소·반품·정산·실제 처리 시간을 기록 | 금붕부부의 유지·개선·중단 판단 |

1~2단계의 공식 조건 수집은 같은 문의로 묶는다. 거래 자격이 불명확한 공급처의 상품 탐색을 반복해 필수 검증을 대신하지 않는다. 공식 명시가 충분하면 결제 시험 없이 자격을 확인할 수 있지만 실제 이행 검증과는 구분한다. 공급처가 부적합하면 다른 후보로 돌아가며, 미확인을 불가능으로 바꾸지 않는다.

## 도구와 역할

| 주체 | 수행 범위 |
| --- | --- |
| Accio 소싱 전문가 | 공급처·거래 조건·상품·견적 조사. 공식 URL·원문 위치·확인일·적용 국가/플랜/상품과 미확인을 제시 |
| Jungle Scout 등 시장 도구 | 대상 Amazon 시장의 경쟁가·수요 자료 확보. 유료 제한·추정 판매량·조회 기간을 표시 |
| 에이전트 | Accio에 범위를 좁혀 지시하고 결과를 원문과 대조. 손익 계산·오류 수정·운영 업무 비교·문서 정합화 |
| 금붕부부 | 공급처·상품·가격·예산·운영 범위 등 주요 결정 및 실무 담당 배정 |

Accio 응답 품질 시험이나 자체 에이전트 개발을 공급처 검증의 선행 과제로 만들지 않는다. 계정 접근과 정책상 허용된 기능만 사용한다. 로그인·유료 제한으로 확보하지 못한 자료는 모름으로 남기며 다른 도구로 확인한 값을 해당 도구 실측으로 표시하지 않는다.

## 조사 결과물

- 공급처별 네 기준의 판정과 직접 근거, 남은 질문·확인 방법.
- 상품별 동일/대체 비교, 실제 공급·배송 견적, 경쟁가·수요 출처, 손익과 반품 시나리오.
- 주문→발주→출고→배송 사고→CS·반품→정산의 처리 주체·우리 업무·예외와 미확인 사항.
- 다음 결정에 필요한 이유와 한계. 문의 발송·자료 작성만으로 공급처 선정이나 수익성 검증을 완료 처리하지 않는다.

재검증에 필요한 결과만 [기록 양식](../records/TEMPLATE.md)에 남기며 현재 판정은 [STATUS.md](../STATUS.md#공급처-판정)에서 갱신한다.

## 판매 착수 조건

1. 한국 거주 상태의 공급처 거래와 Amazon 가입·판매대금 수취 조건을 확인한다.
2. 대상 상품의 브랜드·재판매 권한·분류·인증·수입·세무 조건 및 Amazon 드롭쉬핑/반품 규정을 최신 공식 자료로 확인한다. 국가·출고지·상품에 따라 적용을 구분한다.
3. 공급가·배송·수수료·반품·필수 구독료를 반영한 가격과 손실 가능성을 판단한다. 미확인 비용을 영으로 채우지 않는다.
4. 주문·품절·지연·오배송·반품·정산 처리 방법과 담당, 정산 전 자금·예산·손실 한도를 정한다.
5. [등록 원칙](product-listing-principles.md)에 따라 실제 판매 대상·표시·이미지 권한·배송 약속을 대조하고 판매·관찰 범위를 정한다.

## 실행 한도

- 현재 지출 범위는 [사업 기준](../PROJECT.md#사업-개요), 문의 권한은 [현재 상태](../STATUS.md#다음-행동)를 따른다.
- 유료 구독·샘플 구매·판매 게시·자동 발주는 각 실행 범위가 정해진 뒤 진행한다.
- 거래 조건·가격·품질을 추정해 확인으로 보고하거나, 일반 안내를 우리 계정의 실제 성공으로 바꾸지 않는다.
- 최저가가 아니어도 팔린다거나 상세페이지 개선이 배송·신뢰 열세를 해결한다고 가정하지 않는다.
- 상품을 먼저 정해 놓고 공급처 적합성을 끼워 맞추지 않는다. 수익성 미검증을 사업 불가능의 증거로 쓰지 않는다.
