# 금붕상사 상품 선정 에이전트 설계

도매매 상품 중 판매할 후보를 골라 비교표로 제시하고, 등록 상품의 유지·개선·정리를 판정하는 에이전트의 구조와 운영 방식을 관리한다. 평가 지표와 제외 기준은 [상품 선정 기준](product-selection.md)을 따른다. 구현은 미착수다.

## 설계 원칙

- 수집·계산은 고정 스크립트, 판단이 필요한 단계만 Claude Code가 수행한다. 자금 방침에 따라 별도 서버·유료 LLM API를 전제로 하지 않는다.
- 공식 API로 수집 가능한 데이터만 사용한다. 약관 확인 전 웹페이지 크롤링은 하지 않는다.
- 점수는 판매 가능성 가설이며 판매량 예측이 아니다. 등록 후 실제 노출·주문으로 검증한다.
- 수집 실패·데이터 누락은 영이나 임의값으로 채우지 않고 `모름`으로 표시해 비교표에 남긴다.

## 처리 흐름

| 단계 | 처리 | 수행 |
| --- | --- | --- |
| 1. 후보 생성 | 도매매 상품 목록에서 출발 | 스크립트 |
| 2. 제외 필터 | 초기 제외 기준·가치관 필터 적용 | 규칙 + LLM 분류 |
| 3. 키워드 변환 | 도매 상품명을 고객 검색 키워드 1~3개로 변환 | LLM |
| 4. 데이터 수집 | 검색량·쇼핑 검색 결과·추세·도매 공급가·재고 | 스크립트 |
| 5. 동일 상품 포화도 | 도매 원본 이미지와 쇼핑 검색 상위 결과 이미지·상품명 비교 | 스크립트 |
| 6. 마진·점수 | 최저가·경쟁 중앙가 두 시나리오의 마진 계산 → 기준 미달 제외 → 가중 점수 | 스크립트 |
| 7. 상위 후보 검토 | 후보별 근거·리스크·`모름` 항목 작성. 점수를 새로 만들지 않는다. | LLM |
| 8. 승인 | 비교표를 보고 등록할 상품 승인 | 금붕부부 |
| 9. 판정·보정 | 등록 상품을 [관리 전략](#등록-후-관리-전략)에 따라 진단하고, 결과로 가중치·임계값 재검토 | 에이전트 분석, 금붕부부 결정 |

## 데이터 출처

모든 항목은 2026-10-10 기준 공식 문서 미확인이다. 구현 전 공식 자료나 실제 호출로 확인한다.

| 데이터 | 출처 후보 | 확인할 것 |
| --- | --- | --- |
| 월 검색량 | 네이버 검색광고 API 키워드 도구 | 계정 요건, 무광고 상태 사용 가능 여부, 호출 한도 |
| 상품 수·가격 분포·상품 이미지 | 네이버 쇼핑 검색 API | 조회 가능 범위·호출 한도·응답 필드 |
| 추세·계절성 | 네이버 데이터랩 쇼핑인사이트 | 제공 단위(상대값 여부)·한도 |
| 공급가·배송비·재고·이미지 | 도매매 | API 제공 여부·명세·이용 조건. 없으면 대체 수집 방법과 약관 |
| 상품 등록·노출·클릭·주문 | 네이버 커머스 API, 판매자센터 통계 | 자동 등록·통계 조회 가능 범위, 등록 개수 제한, 중복 등록·재등록 정책 |

## 동일 상품 포화도 측정

- 방법: 키워드별 쇼핑 검색 상위 결과의 이미지를 도매 원본 이미지와 지각 해시로 비교하고, 상품명 유사도를 보조로 쓴다. 조회 범위·유사도 임계값은 미정이다.
- 한계: 판매자가 이미지를 가공하면 놓쳐 과소 추정할 수 있고, 조회 범위 밖 판매자는 포함하지 않는다.
- 검증: 표본 상품을 수동으로 판정해 정확도를 확인한 뒤 임계값을 정한다.

## 비교표 항목

후보·도매 상품 링크, 키워드, 검색량, 경쟁 밀도, 동일 상품 포화도, 최저가·경쟁 중앙가 시나리오별 판매가와 마진, 배송비 부담, 변동성, 점수, 근거·리스크, `모름` 항목, 수집일.

## 운영 방식

- 자동화 수준: 금붕부부가 승인한 상품만 등록하고, 정리 후보도 에이전트가 제안해 금붕부부가 승인한다. 승인 결과와 에이전트 추천의 일치율이 확인된 상품 유형부터 승인 생략을 검토한다.
- 베타 운영: 20개 상품을 8주간 운영하고 승인 상품은 수동 업로드한다〔확인된 것 — 2026-10-10 사용자가 전달한 금붕부부 결정〕. 배정 제안값〔추정치〕: 최저가·경쟁 중앙가 그룹 각 10개, 카테고리·점수가 비슷한 상품을 짝지어 배정. 20개로는 가격 전략 우열을 판정할 수 없으므로 운영 흐름 확인과 판매 원인 설명을 목적으로 한다.
- 실행 주기 제안값〔추정치〕: 발굴 주 1회~격주. 품절·단가 감시는 발굴·관리와 분리해 매일 실행한다.

### 등록 후 관리 전략

베타 기간은 방치를 기본으로 하고 개입을 최소화하며, 8주 후 결과를 보고 전략을 재정비한다〔확인된 것 — 2026-10-10 사용자가 전달한 금붕부부 결정〕. 판매 원인 해석이 흐려지지 않게 하기 위함이다.

| 시점 | 조건 | 조치 |
| --- | --- | --- |
| 상시 | 도매 품절·단종, 공급가 인상으로 마진 기준 미달, 정책 경고 | 판매중지 또는 가격 재조정 |
| 4주차 | 노출 없음 (등록 오류 가능성) | 키워드·카테고리 수정. 그 외 상품은 개입하지 않음 |
| 8주 후 | 베타 결과 | 전략 재정비 |

재정비 시 검토할 선택지: 방치(안 팔려도 유지), 개선(상품명·이미지·키워드·가격 수정), 교체(상품 수 고정, 저성과 상품을 새 후보로), 승자 확장(팔리는 상품의 연관 상품·카테고리·묶음 추가), 휴면(시즌 상품 판매중지 후 재개), 삭제 후 재등록(판매 실적·리뷰 소실과 정책 위험, 효과 모름). 상품을 늘리는 방치형과 상품 수를 고정하는 교체형 중 선택은 품절·단가 동기화의 안정성에 따라 달라진다.
