# 금붕상사 상품 추천 에이전트 설계

상품 추천 에이전트의 범위·구조를 관리한다. 평가 지표와 제외 기준은 [상품 선정 기준](product-selection.md)을 따른다.

## 범위

1. **상품 추천:** 여러 API와 수동 확인으로 데이터를 모아 잘 팔릴 만한 도매매 상품을 추천한다. 산출물은 후보 비교표.
2. **판매 가능 조건 확인:** 추천 상품이 실제로 등록 가능한지 조건을 확보한다. 산출물은 판매 조건서.

담당은 금붕남이다. 판매 조건서 이후의 등록·상품 관리·운영 전략은 운영 담당(금붕녀)의 영역이며 이 에이전트 범위가 아니다.

구현: 1차 코드 `selector/`, 설정 `config/selector.json`, 실행 절차 [product-selector 스킬](../.claude/skills/product-selector/SKILL.md). 검색광고·도매꾹 API는 실호출로 응답 구조를 확인했다(2026-10-10). 전체 흐름을 실제 후보로 돌려 보지는 않았다. 추세·계절성(쇼핑 인사이트)은 네이버 클라우드 가입이 필요해 구현하지 않았다.

## 설계 원칙

- 수집·계산은 고정 스크립트, 판단이 필요한 단계만 Claude Code가 수행한다. 자금 방침에 따라 별도 서버·유료 LLM API를 전제로 하지 않는다.
- 공식 API로 수집 가능한 데이터만 자동 수집한다. 네이버쇼핑은 크롤링하지 않는다. robots.txt가 일반 크롤러를 전면 차단하고, 적발 시 유일한 판매 채널에 영향이 갈 수 있어서다. 에이전트의 브라우저 대리 확인도 같은 이유로 하지 않는다.
- 점수는 판매 가능성 가설이며 판매량 예측이 아니다. 등록 후 실제 노출·주문으로 검증한다.
- 수집 실패·데이터 누락은 영이나 임의값으로 채우지 않고 `모름`으로 표시해 비교표에 남긴다.

## 처리 흐름

| 단계 | 처리 | 수행 |
| --- | --- | --- |
| 1. 후보 생성 | 도매매 상품 목록에서 출발 | 스크립트 |
| 2. 제외 필터 | 초기 제외 기준·가치관 필터 적용 | 규칙 + LLM 분류 |
| 3. 키워드 변환 | 도매 상품명을 고객 검색 키워드 1~3개로 변환 | LLM |
| 4. 검색량 수집 | 대표 키워드의 월 검색수·광고 경쟁도. 도매 공급가·재고·대체 신호는 2단계에서 수집 | 스크립트 |
| 5. 네이버쇼핑 확인 | 검색량 상위 후보의 전체 상품 수·같은 상품 판매자 수·경쟁가 확인. 에이전트가 확인 화면을 만들고 결과를 반영 | 금붕부부 |
| 6. 마진·점수 | 최저가·경쟁 중앙가 두 시나리오의 마진 계산 → 가중 점수 → 비교표 | 스크립트 |
| 7. 상위 후보 검토 | 후보별 근거·리스크·`모름` 항목 작성. 점수를 새로 만들지 않는다. | LLM |
| 8. 판매 가능 조건 확인 | 추천 후보의 [판매 가능 조건](#판매-가능-조건-확인)을 확보하고, 불충족·미확보면 선정 단계로 돌려보낸다 | 스크립트 + 사람 |

1~7단계가 상품 추천, 8단계가 판매 가능 조건 확인이다.

## 데이터 출처

확인일 2026-10-10. 네이버 공식 GitHub 문서는 개편 전 내용이 남아 있어, 네이버 검색·데이터랩 API는 [NAVER API HUB 문서](https://api.ncloud-docs.com/docs/naver-api-hub-overview)를 기준으로 한다. 실제 호출 결과로 다시 대조한다.

**쇼핑 검색 API는 제공되지 않는다.** API HUB 제공 목록에 없고, 개발자센터 신규 신청 목록에도 없다(2026-10-10 사용자 화면 확인). 제3자 자료는 2026-07-31 대체 없이 종료됐다고 전한다(네이버 공지 원문 미확인). 그래서 경쟁 밀도·경쟁가·동일 상품 포화도는 [네이버쇼핑 수동 확인](#네이버쇼핑-수동-확인)으로 얻는다.

| 데이터 | 출처 | 확인된 것 | 모름 |
| --- | --- | --- | --- |
| 월 검색량 | 검색광고 API `GET /keywordstool` ([naver/searchad-apidoc](https://github.com/naver/searchad-apidoc)) | 검색광고 가입 후 API 라이선스(API 키·시크릿·고객 ID) 발급, HMAC 서명. 힌트 키워드 최대 5개. 최근 30일 PC·모바일 검색수(10 미만은 `<10`), 광고 기준 경쟁도 `compIdx`, 연관 키워드 목록. 비즈머니 미충전 계정에서 발급·호출 성공(2026-10-10 실호출) | 호출 한도 |
| 상품 수·경쟁가·같은 상품 판매자 | 네이버쇼핑 수동 확인 | 쇼핑 검색 API 미제공 | — |
| 추세·계절성 (미구현) | NAVER API HUB 쇼핑 인사이트 (분야·키워드별 트렌드 8종) | 네이버 클라우드에서 키 발급, 헤더 `X-NCP-APIGW-API-KEY-ID`·`X-NCP-APIGW-API-KEY`. 클릭량 상대 비율만 제공 | 요금·쿼터 |
| 도매 상품 | 도매꾹 Open API `getItemList` v4.1, `getItemView` v4.6 ([openapi.domeggook.com](https://openapi.domeggook.com/ko)) | API 키 발급 필요. `market=supply`로 도매매 판매중 상품만 조회, 페이지당 최대 200개, 검색어·카테고리 등 조건 1개 이상 필수. 상세: 도매매 단가(수량별 차등 가능), 재판매 준수가격(최저·추천), 재고, 도매매 배송비, 묶음배송, 이미지 사용 허용 여부, KC 인증, 카테고리, 반품 배송비. 일부 상품은 타 사이트 동일 상품 최저·최고가, 단독판매 여부, 인기상품 분류. 목록·상세 실호출 성공(2026-10-10), 숫자가 문자열로 오는 경우가 있다 | 호출 한도, '타 사이트'에 네이버 판매자가 포함되는지 |

- 도매처의 최저판매준수가격이 있으면 판매가는 그 이상이어야 한다. 최저가 시나리오도 이 가격을 하한으로 계산한다.
- 이미지 사용이 허용되지 않은 상품은 자체 이미지가 필요하므로 비교표에 표시한다.

## 네이버쇼핑 수동 확인

- 대상: 검색량 상위 30개 후보〔추정치 — 선별 기준·개수는 제안값〕. 1회 약 1.5~2.5시간〔추정치: 30개 × 3~5분〕.
- 방법: 에이전트가 후보별 도매 이미지·네이버쇼핑 검색 링크·입력칸을 담은 확인 화면(HTML)을 만든다. 사람이 대표 키워드 검색 결과에서 전체 상품 수, 같은 상품 판매자 수(첫 페이지 기준), 같은 상품 가격을 입력하고, 같은 상품이 3개 미만이면 비슷한 상품 가격을 입력한다. 저장한 CSV를 에이전트가 반영한다.
- 한계: 같은 상품 판단은 눈으로 하며 첫 페이지 밖 판매자는 세지 않는다.
- 자동화 검증: 같은 후보의 도매꾹 대체 신호를 함께 기록한다. 수동 확인 결과가 쌓이면 대체 신호가 얼마나 맞히는지 보고 수동 확인을 줄일지 결정한다.

## 마진 계산

- 경쟁가: 수동 확인한 같은 상품 가격이 3개 이상이면 그 가격, 아니면 비슷한 상품 가격〔추정치 — 제안 기준〕. 두 시나리오(최저가·중앙가) 모두 최저판매준수가격을 하한으로 둔다.
- 가정〔추정치〕: 무료배송으로 판매해 도매 배송비를 판매가에서 부담한다. 마진율 분모는 판매가다. 배송비는 도매처의 수량별 차등·비례 규칙으로 1개 주문 기준을 계산하고, 금액비노출·착불이면 `모름`으로 둔다.
- 플랫폼 수수료율은 공식 확인 전이라 비워 두며, 수수료 반영 마진은 `모름`으로 표시한다.
- 점수: 배치 안의 백분위 순위를 가중합한다. 마진 지표는 보수적으로 최저가 시나리오를 쓴다. 가중치는 미확정 제안값이다.

## 판매 가능 조건 확인

추천 후보가 실제로 등록 가능한지 확인한다〔확인 항목과 반려 기준은 2026-10-10 사용자가 전달한 금붕부부 결정〕. 비교표 상위 후보(제안값 25개)를 확인 시점의 최신 도매 정보로 다시 조회한다. 상세페이지가 이미지라 API로 얻을 수 없는 값은 확인 화면에서 사람이 입력한다.

| 확인 항목 | API로 자동 확보 | 사람이 확인 |
| --- | --- | --- |
| 상품번호·판매 옵션·공급가 | 상품번호, 옵션별 추가금·재고·도매매 판매 여부〔옵션 필드 해석은 추정 — 옵션 문서 미확인〕 | 판매할 옵션 선택 |
| 품절·출고 소요·주문 마감 | 판매상태, 재고, 상품준비기간, 평균발송일, 도매 판매기간 종료일, 공급사 휴가 | 주문 마감 시간 |
| 배송비·추가 배송비·묶음배송 | 1개 주문 배송비, 제주·도서산간 추가배송비, 묶음배송 여부·출고지 | — |
| 교환·반품 | 반품 주소, 반품 배송비, 무료배송 판매 시 2배 적용 여부 | 반품 접수 방법 |
| 상세페이지·이미지 사용 범위 | 이미지 사용 허용 여부와 안내문 | — |
| 인증·표시·판매 제한 | KC 인증, 원산지, 제조사, 상품정보고시 품목, `denyMarket`, 최저판매준수가격 | 고시의 '상세정보 별도표기' 항목 실제 값·인증 필요 여부, 상세페이지의 판매 제한 |

반려 기준: **배송·반품 조건이 맞지 않거나 필요한 정보를 확보하지 못하면** 선정 단계로 돌려보낸다.

- 정보 미확보: 위 표의 값이 API에 없거나 사람이 입력하지 않은 경우. 배송비가 착불·금액비노출이라 확정되지 않는 경우, `denyMarket=true`인데 판매 제한 내용을 확인하지 못한 경우(필드 의미 미확인)를 포함한다.
- 배송·반품 조건 불일치: 판매중이 아니거나 품절, 선택 옵션이 품절·판매 불가, 반품 주소·비용이 없는 경우.
- 그 밖의 값은 판매 조건서에 적고 주의로 표시한다: 출고 소요 2일 초과〔추정치 — 표시 기준 제안값〕, 이미지 사용 불허, 묶음배송 불가·조건부, 무료배송 판매 시 반품비 2배, 도매 판매기간 종료 14일 이내, 공급사 휴가, 최저판매준수가격. 이 값으로 등록할지는 운영 담당(금붕녀)이 판단한다.

- 통과: 판매 조건서(`data/reports/<날짜>-sell-conditions.md`)에 등록에 필요한 값을 정리한다. 이 문서가 에이전트의 최종 산출물이다.
- 반려: 사유를 남기고 선정 단계로 돌려보낸다. 비교표의 다음 후보로 채운다.

## 비교표 항목

후보·도매 상품 링크, 키워드, 검색량, 경쟁 밀도, 동일 상품 포화도, 최저가·경쟁 중앙가 시나리오별 판매가와 마진, 배송비 부담, 변동성, 점수, 근거·리스크, `모름` 항목, 수동 확인일. CSV에는 도매꾹 대체 신호를 함께 남긴다.
