# 금붕상사 상품 추천 에이전트 설계

상품 추천 에이전트의 범위·구조를 관리한다. 평가 지표와 제외 기준은 [상품 선정 기준](product-selection.md)을 따른다.

## 범위

1. **상품 추천:** 여러 API로 데이터를 모아 잘 팔릴 만한 도매매 상품을 추천한다. 산출물은 후보 비교표.
2. **판매 가능 조건 확인:** 추천 상품이 실제로 등록 가능한지 조건을 확보한다. 산출물은 판매 조건서.

실행 담당과 미결 역할은 [현재 상태](../STATUS.md#다음-행동)에서 관리한다. 판매 조건서 이후의 등록·상품 관리·운영 전략은 이 에이전트 범위가 아니다.

구현: 코드 `selector/`, 설정 [config/selector.json](../config/selector.json), 실행 절차 [product-selector 스킬](../.claude/skills/product-selector/SKILL.md). 검증 근거는 [실행 기록](../records/2026-10-10-product-selection-agent.md)을 따른다.

## 설계 원칙

- 수집·계산은 고정 스크립트, 판단이 필요한 단계만 Claude Code가 수행한다. 자금 방침에 따라 별도 서버·유료 LLM API를 전제로 하지 않는다.
- [장기 자동화 목표](../PROJECT.md#목적과-목표)에 따라 추천 지표 수집은 자동화한다. 표본 검증과 API로 얻지 못하는 판매 조건 확인에는 현재 사람 입력이 필요하다.
- 공식 API로 수집 가능한 데이터만 자동 수집한다. 판매 채널은 네이버지만 분석 데이터는 네이버에 한정하지 않는다. 네이버쇼핑은 크롤링하지 않는다. 수집 경로 선택의 근거는 [실행 기록](../records/2026-10-10-product-selection-agent.md#결과)을 따른다.
- 점수는 판매 가능성 가설이며 판매량 예측이 아니다. 등록 후 실제 노출·주문으로 검증한다.
- 수집 실패·데이터 누락은 영이나 임의값으로 채우지 않고 `모름`으로 표시해 비교표에 남긴다.

## 처리 흐름

| 단계 | 처리 | 수행 |
| --- | --- | --- |
| 1. 후보 생성 | 도매매 상품 목록에서 출발 | 스크립트 |
| 2. 제외 필터 | 초기 제외 기준·가치관 필터 적용 | 규칙 + LLM 분류 |
| 3. 키워드 변환 | 도매 상품명을 고객 검색 키워드 1~3개로 변환 | LLM |
| 4. 검색량 수집 | 대표 키워드의 월 검색수·광고 경쟁도. 도매 공급가·재고·대체 신호는 2단계에서 수집 | 스크립트 |
| 4-2. 추세·관심도 수집 | 대표 키워드의 검색어 트렌드·쇼핑 클릭 추이(12개월)·블로그·카페 글 수 | 스크립트 |
| 5. 경쟁·가격 수집 | 11번가 상품검색으로 [같은 유형·같은 사진 판매자 수와 경쟁가](#포화도-측정), 대표 키워드의 상품 수·상위 상품명·가격을 수집한다. 검색 결과는 상품명·판매자·가격·배송·같은 사진/유형 여부를 상품 단위로 저장한다 | 스크립트 |
| 5-2. 네이버 카탈로그 조회 | 커머스API로 도매 상품명 검색어의 같은 유형 카탈로그 수와 상품명 일치 카탈로그 수를 조회한다. 점수·추천 조건에 넣지 않는 참고 지표 | 스크립트 |
| 6. 마진·점수 | 최저가·경쟁 중앙가 두 시나리오의 마진 계산 → 가중 점수 → 추천 목록 → 비교표 | 스크립트 |
| 7. 상위 후보 검토 | 대표 키워드가 상품과 맞는지, 비교에 쓴 경쟁 상품과 상품정보고시(소재·크기·구성)가 같은 구매 대상인지 확인하고 후보별 판정·근거·리스크·`모름` 항목 작성. 점수를 새로 만들지 않는다. | LLM |
| 8. 판매 가능 조건 확인 | 추천 후보의 [판매 가능 조건](#판매-가능-조건-확인)을 확보하고, 불충족·미확보면 선정 단계로 돌려보낸다 | 스크립트 + 사람 |

1~7단계가 상품 추천, 8단계가 판매 가능 조건 확인이다. 7단계 판정과 네이버 표본 등 사람의 판정은 `judgments`에 저장하고 최신 판정을 추천에 반영한다. `제외` 판정은 재계산으로 다시 추천되지 않으며 새 판정으로만 바뀐다. 8단계는 대표 키워드·경쟁 수집이 그대로인 현재 근거의 7단계 검토를 마친 후보만 받는다.

## 데이터 출처

**네이버 쇼핑 검색 API는 2026-07-31 대체 없이 종료됐다**〔확인된 것 — [네이버 공지 32530](https://developers.naver.com/notice/article/32530)·[32564](https://developers.naver.com/notice/article/32564), 기존 키 포함 호출 불가〕. 그래서 경쟁 밀도·경쟁가·같은 유형 포화도는 11번가 상품검색으로 대신한다. 위탁 판매자는 통합 솔루션으로 여러 마켓에 같은 상품을 올리므로 11번가 포화도가 네이버 포화도를 반영한다는 가설이며, [검증 표본](../records/2026-10-10-product-selection-agent.md#네이버-대비-표본-검증과-판정-보정--2026-10-14)으로 확인한다.

- 도매처의 최저판매준수가격이 있으면 판매가는 그 이상이어야 한다. 최저가 시나리오도 이 가격을 하한으로 계산한다.
- 이미지 사용이 허용되지 않은 상품은 자체 이미지가 필요하므로 비교표에 표시한다.

## 포화도 측정

도매 상품명에서 만든 검색어로 11번가를 조회한다. 이름 일치는 같은 유형 후보, 이미지 해시 일치는 같은 사진 후보를 찾는 휴리스틱이다. 어느 쪽도 동일 제조사·동일 상품임을 확정하지 않는다.

- **같은 유형 판매자 수:** 검색어의 두 글자 이상 단어 중 상품명에 포함된 비율로 판정한다. 띄어쓰기는 무시하며 판정 임계값·조회 상한은 설정의 `competition`에서 관리한다.
- **같은 사진 판매자 수:** 썸네일 dHash 거리로 판정한다. 이미지 조회 실패 수를 함께 기록하고 가공된 사진·상위 조회 범위 밖 경쟁자는 놓칠 수 있다.
- **경쟁가:** `pricing.min_matched_for_same_product_price` 이상의 비교 가능한 가격을 확보한 같은 사진 집합 → 같은 유형 집합 → 대표 키워드 검색 결과 순으로 선택한다. 비교 가능한 가격은 다음을 뺀 것이다〔추정치 — 혼입 제거용 제안 기준, 판정 정확도 미검증〕.
  - 배송 조건: 11번가 배송 표시가 `무료`가 아닌 상품(`조건부무료`·`착불/선결제`). 한 개 주문의 배송비를 몰라 무료배송 판매가와 섞지 않는다. 그 표시가는 고객 결제 총액의 하한이므로 최저가 시나리오에만 하한으로 쓴다.
  - 수량·치수: 상품명에 표기된 수량(개입·세트 등)·가로×세로가 도매 상품과 다른 상품.
  - 다른 종류: 같은 유형 집합에서 경쟁 상품명 단어 중 도매 상품명에 있는 비율이 `competition.type_reverse_overlap` 미만인 상품.
  - 저가: `pricing.drop_outliers`이면 유효 가격이 세 개 이상일 때 중앙값의 절반 미만.
- 같은 사진 가격이 부족해 다른 집합을 쓸 때는 같은 사진 가격(배송 조건 무관)을 최저가 시나리오의 하한으로 쓴다. 선택한 집합의 상위÷하위 4분위 비율이 `pricing.dispersion_warn`을 넘으면 혼입 의심으로 표시한다. 같은 사진·같은 유형 가격이 모두 부족한 후보는 추천하지 않고 비교표의 `비교 가격 부족 — 확인 대상`에 남긴다. 상품 단위 기록이 없는 이전 수집분은 비교 조건 미확인으로 표시하며 `compete --redo`로 재수집한다.
- **한계:** [네이버 대비 표본](../records/2026-10-10-product-selection-agent.md#네이버-대비-표본-검증과-판정-보정--2026-10-14)은 작고 유형 판정 정확도도 미검증이다. 11번가 수치를 네이버 전체 경쟁으로 환산하지 않는다. 진입 장벽의 자동 측정 출처는 모름이다.

## 마진 계산

- 경쟁가는 [포화도 측정](#포화도-측정)을 따르며 최저가·중앙가 두 시나리오 모두 도매처 최저판매준수가격을 하한으로 둔다.
- 가정〔추정치〕: 무료배송 판매가에서 도매 공급가(기본 옵션)와 한 개 주문 배송비를 차감한다. 마진율 분모는 판매가다. 착불·금액비노출 배송비는 `모름`으로 둔다. 반품 등 전체 변동비를 반영한 [주문당 기여이익](../PROJECT.md#운영-및-평가)과는 다르다.
- 옵션 추가금이 있으면 도매매에서 팔 수 있는 가장 비싼 옵션 기준의 최저가 마진을 함께 표시한다. 반품은 반품률을 몰라 마진에 넣지 않고, 반품 1건의 공급처 반품배송비(무료배송 판매 시 2배 조건 반영)가 최저가 기준 몇 건의 마진에 해당하는지 표시한다. 두 값을 추천 판정에 넣을지는 [미결 과제](../STATUS.md#미결-과제)다.
- 수수료율은 `pricing.platform_fee_rate`를 사용한다. 미설정이면 수수료 반영 마진은 `모름`이다. 추천 판정의 마진 기준은 `scoring.margin_basis`다. `gross`(현행)는 수수료 차감 전, `net`은 차감 후이며 수수료율이 비어 있으면 추천하지 않는다. 스마트스토어 수수료의 공식 조건은 미확인이다.
- 네이버 보정〔추정치〕: 11번가 경쟁 최저가·중앙가에 [설정](../config/selector.json)의 `naver_calibration` 계수를 곱한다. 같은 사진 판매자 수 보정은 표시용이다. [표본·산정 근거](../records/2026-10-10-product-selection-agent.md#좋은-쪽-표본-검증과-네이버-보정--2026-10-14)에 따른 제한적인 추정이며 표본이 쌓이면 다시 계산한다.
- 점수는 배치 안의 백분위 순위를 가중합한다. 마진은 최저가 시나리오를 쓰고, `scoring.required` 지표가 없으면 점수를 매기지 않는다. 그 외 누락 지표는 가중합에서 제외하고 누락 목록에 남긴다.
- 추천은 점수가 있는 후보 중 경쟁가 출처가 같은 사진·같은 유형이고 네이버 보정 후 중앙가 시나리오 마진이 설정 조건을 충족하고 최저가 시나리오가 적자가 아니며 `제외` 판정이 없는 대상을 고른다. 추천 후보는 `scoring.sensitivity`의 가격 가정 대안(저가 제거·같은 사진 최소 건수·네이버 보정)으로 다시 계산해 상품별 조건을 잃으면 그 가정을 표시한다. 순위·키워드별 상한·가중치·임계값의 원본은 [설정](../config/selector.json)의 `scoring`이다. 모두 미확정 제안값이며 판매 승인 기준이 아니다. **추천 목록 상한과 판매 실험 수량은 별개다.**
- 검색 추세는 최근 세 달과 그 전 세 달의 평균 비율, 계절 지수는 직전 달과 열두 달 평균의 비율이다〔계산 방식; 판매 예측 아님〕. 쇼핑 분야는 도매 카테고리로 우선 매핑하며 데이터 부족 시 다른 분야를 조회한다. 분야별 적합성과 대표 키워드는 상위 후보 검토에서 확인한다. 블로그·카페 지표는 참고 자료이며 점수에 넣지 않는다.

## 판매 가능 조건 확인

추천 후보가 실제로 등록 가능한지 확인한다. 확인 항목과 반려 기준은 아래에서 관리하며, 적용 이유는 [공동 결정 근거](../records/2026-10-10-product-selection-agent.md#범위-재정의--2026-10-10)를 참조한다. `verify-export`는 경쟁 수집 완료(`checked`) 상태이고 현재 근거로 7단계 검토를 마친 추천 후보를 `verification.top`까지 최신 도매 정보로 다시 조회한다. 추천 상한도 함께 적용되므로 설정의 확인 상한만큼 항상 출력되는 것은 아니다. `--nos`는 대상을 직접 지정하며, 검토가 없거나 이전 근거의 검토이거나 `제외` 판정인 후보가 있으면 실행하지 않는다. 상세페이지가 이미지라 API로 얻을 수 없는 값은 확인 화면에서 사람이 입력한다.

| 확인 항목 | API로 자동 확보 | 사람이 확인 |
| --- | --- | --- |
| 상품번호·판매 옵션·공급가 | 상품번호, 옵션별 추가금·재고·도매매 판매 여부〔옵션 필드 해석은 추정 — 옵션 문서 미확인〕 | 판매할 옵션 선택 |
| 품절·출고 소요·주문 마감 | 판매상태, 재고, 상품준비기간, 평균발송일, 도매 판매기간 종료일, 공급사 휴가 | 주문 마감 시간 |
| 배송비·추가 배송비·묶음배송 | 1개 주문 배송비, 제주·도서산간 추가배송비, 묶음배송 여부·출고지 | — |
| 교환·반품 | 반품 주소, 반품 배송비, 무료배송 판매 시 2배 적용 여부 | 반품 접수 방법 |
| 상세페이지·이미지 사용 범위 | 이미지 사용 허용 여부와 안내문 | — |
| 인증·표시·판매 제한 | KC 인증, 원산지, 제조사, 상품정보고시 품목, `denyMarket`, 최저판매준수가격 | 고시의 '상세정보 별도표기' 항목 실제 값·인증 필요 여부, 상세페이지의 판매 제한 |

반려 기준: **배송·반품 조건이 맞지 않거나 필요한 정보를 확보하지 못하면** 선정 단계로 돌려보낸다.

- 정보 미확보: 위 표의 값이 API에 없거나 사람이 입력하지 않은 경우. 배송비가 착불·금액비노출이라 확정되지 않는 경우, `denyMarket=true`인데 판매 제한 내용을 확인하지 못한 경우(필드 의미 미확인)를 포함한다.
- 배송·반품 조건 불일치: 판매중이 아니거나 품절, 선택 옵션이 품절·판매 불가, 반품 주소·비용이 없는 경우.
- 주의 표시의 수치 기준은 설정의 제안값이다. 그 밖의 값은 판매 조건서에 적고 주의로 표시한다: 설정 `verification.prep_warn_days` 초과, 이미지 사용 불허, 묶음배송 불가·조건부, 무료배송 판매 시 반품비 2배, 설정 `verification.sale_end_warn_days` 이내 판매기간 종료, 공급사 휴가, 최저판매준수가격. 추천 단계의 통과가 게시 승인이나 판매 착수 승인은 아니다. 등록 단계에서는 [게시 판단](../agents/product-listing/data-contract.md#상태와-게시-판단)과 [사업 착수 조건](execution-plan.md#착수-조건)을 함께 적용한다.

- 통과: 판매 조건서(`data/reports/<날짜>-sell-conditions.md`)에 등록에 필요한 값을 정리한다. 이 문서가 에이전트의 최종 산출물이다.
- 반려: 사유를 남기고 선정 단계로 돌려보낸다. 비교표의 다음 후보로 채운다.

## 검증 범위

추천 결과의 품질은 [추천 에이전트 평가](product-selection.md#추천-에이전트-평가)를 따른다. 현재 자동 추천은 검색 수요·수수료 확인을 필수 조건으로 강제하지 않으며, 의미 검토는 판매 조건 확인 전에만 강제한다. 판매준수가 적용 전 경쟁 관측가와 적용 후 제안 판매가를 분리해 검토해야 한다. 경쟁가의 배송·수량·치수·종류 정규화는 상품명·배송 표시에 의존하는 휴리스틱이라 옵션별 경쟁 결제 총액의 대조를 대신하지 않는다. 검색수의 `<10`은 계산에서 확실한 하한(알려진 값 + 0)을, 표시에서 범위를 쓴다. 합성 입력의 한계는 [사전 평가](../records/2026-10-10-product-selection-agent.md#추천-품질-사전-평가--2026-10-14), 경쟁 배송 조건·보정 계수 민감도는 [재조회 평가](../records/2026-10-10-product-selection-agent.md#자동-추천-결과물-평가--2026-10-14), 저장된 비교표의 옵션·소재 충돌과 가격 가정 민감도는 [결과물 평가](../records/2026-10-10-product-selection-agent.md#저장된-실제-추천-결과-평가--2026-10-14), 이를 반영한 변경과 로컬 비교표의 추천 변화는 [개선 기록](../records/2026-10-10-product-selection-agent.md#평가-결함-개선--2026-10-15)을 따른다.

오프라인 검증은 저장소 루트에서 `.venv/bin/python -m unittest discover -s tests`로 실행한다. 파싱·계산·상태 전환을 확인하며 실호출 성공, 상품 적합성이나 판매 효과를 보장하지 않는다.

현재 `verify.evaluate`는 공급가 누락·선택 옵션 재고 미확인을 모두 차단하지 않으며, 고시·인증은 사람의 확인 표시를 사용한다. `denyMarket=true`는 사람의 확인 표시와 관계없이 반려한다. 따라서 통과 상태를 위 확인 항목 전체의 완전성 증명으로 사용하지 않는다. 판매 조건서를 인계하기 전에 누락과 원문을 대조하고, 구현 보완 과제는 [현재 상태](../STATUS.md#미결-과제)에서 관리한다.
