# 상품 등록 원칙

네이버 스마트스토어 위탁판매의 공통 기준이다. **구매 조건이 드러나는 검색어를 공략하고, 그 조건에 맞는 상품임을 명확히 보여준다.** 에이전트의 처리 구조는 [설계](../agents/product-listing/design.md), 상품 선정 평가는 [선정 기준](product-selection.md)에서 관리한다.

## 고객과 검색 전략

- 핵심 고객 가설은 필요한 조건은 있지만 상품·판매처를 아직 결정하지 않은 고객이다. 네이버 이용자 전체의 특성이나 다른 플랫폼과의 배타적 역할 분담으로 단정하지 않는다.
- 상품 등록은 고객이 찾는 물건·사용 상황·선택 조건을 정의하는 데서 시작한다. 공급처 상품명에 인기어를 덧붙이지 않는다.
- 상품명·태그는 후보별 검색량과 실제 경쟁 상품을 확인하고, 대안끼리 수요·구매 의도·상품 적합성·경쟁 판매 조건을 비교한 뒤 선택한다. 추가 후보와 기존안의 재검토에도 [조사 절차](../agents/product-listing/workflow.md#조사와-방향-판단)를 적용한다. 긴 검색어나 낮은 경쟁도가 곧 판매 기회라는 가정을 두지 않는다.
- 무광고 신규 스토어의 첫 관문은 검색 적합성이다. 노출 이후 선택받을 가격·배송·정보·신뢰도 함께 갖춘다. 브랜드 충성도보다 첫 구매의 신뢰를 우선한다.
- 상위노출은 목표이며 보장값이 아니다. 특정 어순·키워드 반복·임의의 SEO 점수를 순위 보장으로 제시하지 않는다.

## 등록 항목별 역할

| 항목 | 작성 기준 |
| --- | --- |
| 카테고리 | 실제 상품의 주된 기능·형태에 맞는 세부 분류를 확인하고 선택 이유를 남긴다. 경쟁 회피만을 위한 오등록 금지 |
| 속성·브랜드·모델 | 확인된 값을 전용 필드에 입력한다. 판매처를 제조 브랜드로 만들거나 상세이미지로 필드 입력을 대신하지 않는다 |
| 상품명 | 상품 종류와 중요한 선택 조건을 간결하게 표현한다. 확인된 브랜드·모델을 사용하며 동의어 나열·홍보문구·근거 없는 성능 수식은 제외한다 |
| 태그 | 다른 필드로 표현하기 어려운 관련 정보를 보완한다. 태그 사전·채널 허용 여부를 확인하고 카테고리·브랜드·판매처·홍보문구를 채워 넣지 않는다 |
| 대표 이미지 | 실제 판매 상품의 외형·색상·구성이 쉽게 식별되어야 한다. 소품·다른 옵션이 기본 구성으로 오인되지 않게 한다 |
| 상세페이지 | 검색 당시의 구매 질문에 답한다. 적합성·장점의 근거·옵션 차이·제약을 쉽게 찾고 비교하게 한다 |
| 가격·옵션·배송·반품 | 표시 상품과 실제 구매 구성을 일치시키고 고객 부담과 제공 조건을 명확하게 안내한다 |
| Page Title·Meta description | 채널에서 제공하는 검색 설정으로 취급한다. 핵심 내용을 정확히 요약하며 쇼핑 순위 상승 효과를 가정하지 않는다 |

## 상세 콘텐츠와 공급처 자료

- 정보 순서는 구매 판단의 중요도로 정한다. 치수·호환성·사용 조건 등 해당 상품의 결정 요인을 앞에서 해결한다. 감성 도입·장점 나열·FAQ를 모든 상품에 강제하지 않는다.
- 원본이 충분하고 읽기 쉬우면 활용한다. 중요한 정보가 묻혀 있으면 요약·재배치하며, 부족하면 근거를 확보해 보완한다. 새로운 사실이 없어도 이해와 탐색을 개선하는 편집은 가능하다. 반복에는 구매 판단상 역할이 있어야 한다.
- 각 문장·이미지는 어떤 구매 질문에 답하며 어떤 근거를 사용하는지 설명할 수 있어야 한다. 근거 없는 차별점·후기·브랜드 이야기·성과 수치는 만들지 않는다.
- 공급처 표기, 자체 확인, 가설, 모름을 구분한다. 이미지 안의 설명도 읽어 공급처 기재 사실로 반영하며, 자체 시험이 없다는 이유만으로 기재 자체를 모름으로 처리하지 않는다. 공급처 성능 주장을 자체 시험·인증 또는 더 강한 보장으로 바꾸지 않는다. 사진만으로 수치·재질·호환성을 확정하지 않는다.
- 사용·편집 권한의 범위를 확인한다. 편집으로 제품의 실제 외형·색상·구성·성능을 왜곡하지 않는다. 추가 촬영·제작이 필요하면 이유와 확보할 자료를 제시한다.
- 상품명·대표사진·옵션·가격·상세설명은 같은 판매 대상을 설명해야 한다. 공용 이미지의 다른 규격을 임의로 판매 옵션에 추가하지 않는다.
- 공급처 거래 조건을 소비자 안내로 자동 복사하지 않는다. 발송·교환·반품은 판매자가 이행할 수 있는 조건으로 작성한다. 필수 표시·인증의 미확인을 해당 없음으로 대체하지 않는다.

## 상세페이지 포맷

포맷 참고는 [스퀘어상점의 데스크 매트 상세페이지](https://smartstore.naver.com/papabog327/products/6854607391)다. 확인된 것 — 2026-10-13 사이드 브라우저의 좁은 화면에서 도입·제품 정보·옵션 사진·특징 설명을 확인했다. 흰 배경, 큰 사진, 중앙 정렬의 짧은 제목과 설명, 넉넉한 블록 간 여백이 관찰됐다. 스토어 전체 상품의 공통 규격이나 판매 효과를 검증한 것은 아니다.

아래는 이 포맷을 적용하는 작성 기준이다.

- 흰 배경의 세로 흐름을 기본으로 하며, 사진·짧은 제목·간결한 설명으로 구매 질문별 블록을 구성한다. 한 블록에는 하나의 판단 주제를 담는다. 상세페이지 도입은 작은 영문 소제목 → 한글 상품명 → 구성 설명 → 규격·색상 순으로 배치한다. 영문 소제목은 대문자·작은 글씨·넓은 자간으로 표시하며 한글 상품명의 상품 종류와 핵심 소재를 일치시킨다. 예를 들어 “PU 인조가죽 데스크 매트”는 “PU LEATHER DESK MAT”으로 쓰고 소재를 임의로 생략하거나 천연가죽으로 오인할 표현으로 바꾸지 않는다. 확인되지 않은 소재는 어느 언어에도 추가하지 않는다. 한글 상품명은 상품 종류와 필요한 소재를 표현하는 담백한 이름으로 쓴다. 구성은 제목 아래 설명에, 규격·색상은 그 다음 줄에 배치해 상품명과 옵션 정보를 구분한다. 검색용 등록 상품명과 상세페이지 도입 제목을 동일한 문자열로 강제하지 않는다. 작위적인 감성 문구·슬로건은 붙이지 않는다. 고객 본문에 “공급처 설명”, “공급처 안내” 등 출처 수식을 반복하지 않는다. 출처·검수 메모는 별도 확인 문서에서 관리하고, “공급처 표기 기준” 같은 필요한 기준 표시와 판매 옵션·참고 사진의 구분은 유지한다.
- 제품 사진은 되도록 전부 활용한다. 원본의 사용 장면·옵션·치수·세부 확대·관리 사진을 먼저 목록화하고 구매 질문별로 배치한다. 간결함을 이유로 사진을 임의로 줄이지 않으며, 중복·무관 이미지 등을 제외하면 이유를 남긴다. 사진은 제품과 확인할 특징이 잘 보이도록 배치하고 설명은 가까이에 둔다. 표시 크기는 파일 전체가 아닌 실제 사용할 사진 영역의 픽셀 크기를 기준으로 정하며, 원본 영역보다 확대하지 않는다. 작은 사진은 관련 사진끼리 나란히 묶고 좁은 화면에서는 축소·줄바꿈한다. 확대나 AI 업스케일을 화질 복원으로 간주하지 않으며 충분한 크기의 원본 확보를 우선한다. 사진과 긴 문구를 중첩하지 않는다.
- 이미지 속 제목·설명은 읽을 수 있는 본문 텍스트로 옮기고, 사진 영역에서는 옮긴 문구를 잘라 중복을 없앤다. 원문의 의미·수치·적용 조건은 보존하며 사용자가 지정한 문장은 그대로 쓴다. 치수 화살표·옵션 라벨처럼 사진과 함께 있어야 이해되는 표시는 유지한다. 제품 일부나 필요한 표시를 훼손해야만 분리할 수 있다면 원본을 유지하고 사유를 남긴다.
- 제목과 본문의 크기·굵기로 위계를 만들고 여백으로 블록을 구분한다. 모바일에서 단어 중간이 끊기지 않도록 줄바꿈을 조정하고, 긴 문자열은 가로 넘침 없이 표시한다. 짧은 도입·특징 설명은 중앙 정렬을 기본으로 하되, 비교표·규격·긴 주의사항은 읽기 쉬운 정렬을 선택한다.
- 규격은 숫자 표와 함께 측정 위치를 보여주는 원본 사진·도식을 배치한다. 원본에 없으면 근거가 있는 범위에서 도식을 구성하고 측정 기준을 추정하지 않는다. 옵션은 비교 이미지와 간결한 표로 정리한다. 필요한 조건과 주의사항을 글씨 축소나 접힘으로 숨기지 않는다.
- 간결함은 문구의 반복과 장식을 줄이는 기준이다. 필요한 정보를 빼거나 페이지 전체 길이·사진 수·글자 수를 일률적으로 제한하지 않는다. 블록 순서는 해당 상품의 구매 결정 요인에 맞춘다.
- 레퍼런스의 상품명·키워드·문구·이미지·성능 주장·거래 조건은 재사용하지 않는다. 모든 내용과 자산은 대상 상품의 근거와 권한에서 작성한다.

글꼴·크기·간격의 구체적인 값은 구현 시 미리보기에서 정하고 PC·모바일 및 실제 채널 화면으로 확인한다. 레퍼런스의 CSS 수치를 확인한 값으로 제시하지 않는다.

## 조사와 품질 판단

- 자동완성·연관어·유사 상품·실제 유입어는 검색 언어를 찾는 자료다. 검색량·판매량 자체를 입증하지 않는다. 경쟁 리뷰·질문은 구매 질문을 찾는 자료이며 우리 상품의 사실 근거가 아니다.
- 관측에는 출처·확인일·검색 환경·상품 및 옵션 범위를 붙인다. 수치는 [수치 표기](../AGENTS.md#수치-표기)에 따른다. 수요·경쟁·비용의 미확인을 임의의 값이나 영으로 채우지 않는다.
- 결과물은 검색어 선택 이유, 상품 적합성, 경쟁 판매처 대비 선택 이유, 정보 접근성, 사실·거래 조건 일치로 평가한다. 분량·문서 형식·구조 검사 통과를 의미 품질로 취급하지 않는다.
- 등록 후 확보 가능한 유입·구매·문의·반품 자료로 가설을 수정한다. 노출 순위만으로 성공을 판단하지 않으며 노출 부족 상태에서 전환 효과를 단정하지 않는다. 손익·운영 평가는 [사업 기준](../PROJECT.md#운영-및-평가)을 따른다.
