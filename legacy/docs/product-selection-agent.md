# 보관 선별 도구

도매매 후보의 국내 가격 비교·검토·판매 조건서 생성을 재현하는 구현이다. Amazon 공급처 조사에 사용하지 않는다. 환경·자료 위치는 [보관 코드 안내](../README.md)를 따른다.

## 실행 흐름

`legacy/`에서 `../.venv/bin/python -m selector <명령>`으로 실행한다. 데이터 변경은 `--data-dir <별도 자료 경로>`를 하위 명령 앞에 지정해 분리한다. 명령별 인자는 `--help`를 확인한다.

| 순서 | 명령 | 처리 |
| --- | --- | --- |
| 1 | `search`, `detail` | 목록·상세 수집과 규칙 제외. 재수집은 `detail --refresh`, 별도 표본은 `search --skip-db` |
| 2 | `triage-export`, `triage-import` | 상품별 제외 사유 또는 대표 검색어 입력 |
| 3 | `measure`, `trend`, `compete`, `catalog` | 검색량·관심도·11번가 경쟁·네이버 카탈로그 자료 수집 |
| 4 | `manual-export`, `manual-import`, `judge` | 네이버 수동 관측·상품 판정 저장. 수동 가격은 자동 계산에 직접 반영되지 않음 |
| 5 | `review-export`, `review-import`, `report` | 현재 근거 검토 후 선별표 생성. 순위·추천 아님 |
| 6 | `verify-export`, `verify-import` | 공급 재조회·옵션/배송/고시 등 수동 입력·조건서 또는 반려 사유 출력 |

API 명령 일부는 실패 상품을 건너뛰며 일부는 중단될 수 있다. 종료 코드와 미처리 범위를 확인한다. 현재 외부 API 접근·요금은 재확인이 필요하며 우회 수집하지 않는다.

## 데이터 출처

코드 연결 대상은 도매꾹 `getItemList/getItemView`, 검색광고 키워드 도구, 11번가 `ProductSearch`, NAVER API HUB, 네이버 커머스API다. 호출·표본 검증의 당시 사실은 [데이터 소스 기록](../../records/2026-10-10-product-selection-agent.md#데이터-소스-선택과-실호출--2026-10-10)에 있다. 현재 사용 가능성을 보장하지 않는다.

## 계산과 선별

같은 유형(상품명 겹침)·같은 사진(이미지 해시) 일치는 비교 후보를 찾는 휴리스틱이며 동일 규격·수량의 확정이 아니다. 설정 원본은 [selector.json](../config/selector.json)이다.

경쟁 관측가, 네이버 보정 추정가, 최저판매준수가 적용 시나리오를 구분한다. 선별은 설정의 같은 사진 가격 근거·마진 조건과 제외 판정을 사용한다. 수수료·옵션·반품 처리와 가격 가정의 한계는 [검증 기록](../../records/2026-10-10-product-selection-agent.md)에 있으며 현재 사업의 손익 합격선으로 사용하지 않는다.

## 검토와 인계의 유효성

- triage 입력은 상품번호 `no`, `exclude`(사유 또는 null), `keywords` 배열이다.
- review 입력은 `no`, 내보낸 `evidence_at`, `decision_revision`, `verdict`, `rationale`, `risks`, `unknowns`다. 판정 문자열은 `판매 실험 검토 가능`, `추가 확인`, `제외`이며 사업상 판매 승인이 아니다.
- 상품·규격·수량·소재·경쟁 가격의 일치를 검토한다. 입력 지표 외 값을 만들지 않고 정보 부족과 실제 불일치를 구분한다.
- `evidence_at`·판정 버전은 그대로 반환한다. 근거 변경·새 판정·중복·필수값 누락은 검토 재반영을 차단한다. 최신 export부터 재검토하며 식별값만 바꿔 재사용하지 않는다.
- verify는 현재 선별·검토 통과를 요구하고 공급 재조회 후에도 확인한다. 화면·CSV는 `batch_id`와 실행 ID로 연결하며 혼합·오래된 입력은 거부한다.
- 공급가·옵션 재고 등 구현이 완전히 차단하지 못하는 누락이 있다. 조건서 통과를 판매 조건 전체의 증명으로 쓰지 않는다. 반품 접수 방법 등 주의 항목도 원문과 대조한다.

## 검증

[오프라인 시험](../tests/test_selector.py)은 파싱·계산·근거 변경·검토·인계 동작을 확인한다. 실호출·시장 타당성·상품 판매성은 별도다. 가격 혼입·보정·미실행 검증의 근거는 [기록](../../records/2026-10-10-product-selection-agent.md)을 참조한다.
