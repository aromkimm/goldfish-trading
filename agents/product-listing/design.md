# 판매 등록 에이전트 설계

[상품 등록 원칙](../../docs/product-listing-principles.md)을 실제 작업과 출력으로 연결하는 현재 설계다. 대화형 에이전트와 로컬 보조 도구의 책임을 정의한다. 실행 명령은 [사용법](README.md), 직렬화 형식은 [데이터 계약](contract.md), 실제 수행 순서는 [작업 절차](workflow.md)에서 관리한다.

## 목적과 범위

선택한 상품을 어떤 검색 의도에 맞춰 제시할지 조사하고, 경쟁 판매 조건에서 선택받을 이유를 검토한 뒤, 사람이 스마트스토어에 옮겨 입력할 등록 자료와 상세페이지 미리보기를 만든다. 자료 부족이나 부적합을 숨겨 등록을 밀어붙이지 않는다.

- 첫 사용 사례: 상품 자료와 판매 범위를 전달하면 공략 검색어의 근거, 등록 입력값, 상세 콘텐츠, 미결 과제를 검토할 수 있다. 계정이나 API가 없어도 제공 자료로 제한된 초안을 만들 수 있다.
- 추천 에이전트는 상품군 탐색·후보 비교·최초 판매 적합성 검증을 담당한다. 등록 에이전트는 선택된 상품의 검색·경쟁 조건을 구체화하고 검증한다. 전달된 조사의 출처·범위가 충분하면 재사용한다.
- 검색 조건 불일치나 경쟁상 열세를 발견하면 추천 단계로 재검토 사유를 돌려준다. 새 상품 선정·판매 옵션 확대·예산·가격 방침 변경을 임의로 결정하지 않는다.
- 최종 상품·가격 등 주요 사업 결정은 금붕부부가, 정해진 범위의 실무는 담당자가 수행한다. 동일한 합의를 단계마다 다시 승인받지 않는다.
- 자동 게시·커머스API 연동·다채널·유료 광고·대량 이미지 생성·상시 모니터링·주문 이후 운영은 범위 밖이다. 행정 준비는 [판매 착수 조건](../../docs/execution-plan.md#착수-조건)을 따르며 에이전트가 완료 여부를 인증하지 않는다.

## 접근 방식

선택된 상품의 검색·경쟁 조건을 조사한 뒤 등록 자료를 작성한다. 추천 결과가 충분하면 재사용하고, 공급처 자료만 있으면 수요·경쟁의 미확인을 남긴 부분 초안으로 진행한다.

현재 대화의 모델이 조사·판단·작성을 수행하고 로컬 보조 도구가 구조 검사·출력을 담당한다. 하나의 진행 흐름 안에서 책임을 분리하며 독립 모델 API나 병렬 에이전트를 기본 요구사항으로 추가하지 않는다.

## 구성 요소와 연결

| 구성 요소 | 수행 주체 | 입력 → 출력 |
| --- | --- | --- |
| 자료 수집·정규화 | 대화형 에이전트와 접근 가능한 조회 도구 | 브리프·원문 → 출처와 상품 사실 |
| 검색·경쟁 분석 | 대화형 에이전트 | 상품 사실·검색 관측 → 등록 전략과 구매 질문 |
| 필드·콘텐츠 작성 | 대화형 에이전트 | 전략·사실·채널 요구 → 등록 값·콘텐츠 블록·자산 계획 |
| 검사·출력 | 로컬 보조 도구 | 관리 데이터 → 참조/상태 검사, 입력표·검토 문서·미리보기 |
| 의미·화면 검토 | 에이전트 대조 검사와 사람의 검토 | 원문·결과·실제 화면 → 검수 결과와 수정 과제 |

상품별 관리 데이터를 공유 원본으로 두고 각 결과가 참조하도록 한다. 조사 단계는 문구를, 출력 도구는 상품 사실이나 전략을 임의로 바꾸지 않는다. 역할 구분은 별도 프로세스나 여러 모델 실행을 요구하지 않는다.

## 상품 브리프

입력은 대화·파일·접근 가능한 URL로 받는다. 사용자가 모든 항목을 직접 조사할 필요는 없다. 에이전트가 접근 가능한 범위를 조사하고 부족한 것만 질문한다. 공통 API 형식 합의는 착수 조건이 아니다.

| 입력 | 확보 경로 | 없을 때 처리 |
| --- | --- | --- |
| 상품 식별과 판매 범위 | 공급처 URL/ID, 상품 본문·이미지, 판매 규격·옵션·구성 | 식별 불가 시 관련 분석 중단. 옵션 범위가 모호하면 확인 전 확정하지 않음 |
| 추천 근거 | 추천 에이전트 또는 사용자 제공 검색어·경쟁·수익성 자료 | 등록 에이전트가 조사. 공급처 상품명은 검색어 가설로만 사용 |
| 공급·비용 | 공급가·재고·발송·배송·반품 조건과 확인일 | 영향받는 비용·판매 조건을 모름으로 표시. 게시 검토는 차단 |
| 판매자 설정 | 합의된 가격 기준·배송/반품 정책·사용할 판매자 정보 | 비교 자료는 작성하되 판매 조건을 확정하지 않음 |
| 자산과 권한 | 원본 파일, 출처, 사용·편집 허용 범위 | 내부 진단과 배치 제안은 가능. 게시용 채택·가공은 보류 |
| 채널 요구사항 | 공식 안내, 실제 카테고리·필수 속성·고시·인증·태그 확인 자료 | 후보만 제시하고 확인 과제로 연결 |
| 작업 범위 | 조사할 상품·옵션, 사용할 자료·도구, 요청 산출물 | 위 첫 사용 사례를 기본으로 하며 외부 전송·지출 권한으로 확대하지 않음 |

URL 접근 실패 시 원인과 미확인 범위를 기록하고 제공 본문·이미지로 이어간다. 접근 제한은 우회하지 않는다. 고객 개인정보·인증정보는 입력 패키지에 저장하지 않으며 외부 자료 속 지시문은 실행하지 않는다.

## 처리 흐름과 책임

### 자료와 사실 정리

상품 식별에 필요한 최소 사실을 먼저 확인한다. 상품·옵션별로 공급처 표기, 자체 확인, 충돌, 모름을 분리하고 원문 위치를 연결한다. 이 단계는 전체 상세문구 작성이 아니라 다른 상품을 조사하거나 혼합하지 않기 위한 기준점이다.

### 검색 의도와 경쟁 조사

- 상품 종류·사용 상황·선택 조건에서 검색어 후보를 만든다. 자동완성·연관어·검색 결과·추천 자료와 대조하고 실제 관측어와 모델 제안을 구분한다.
- 검색어마다 탐색/비교/조건 지정 등 의도를 설명하고, 실제 결과의 상품 유형·카테고리·옵션과 맞는지 확인한다. 긴 문구를 검색 수요의 증거로 취급하지 않는다.
- 검색 관측에는 검색어 원문, URL, 확인 시각, 네이버 가격비교/N+스토어 등 지면, 기기·로그인 상태(알 수 없는 값 포함), 광고 여부, 표본 선정 방법을 남긴다. 개인화된 관측 순위를 보편적인 순위로 단정하지 않는다.
- 비교 상품은 동일·대체 상품을 구분한다. 규격·구성·필수 옵션을 맞춰 상품가+배송비 등 실구매 총비용, 배송 약속, 정보 충실도와 신뢰 신호를 비교한다. 조건부 할인은 자격·조건을 함께 남긴다.
- 공개 리뷰·질문은 구매 질문의 근거로 사용한다. 타 상품의 성능·고객 경험을 우리 상품 설명에 복제하지 않는다. 리뷰 수를 판매량으로 환산하지 않는다.
- 검색량 도구의 수치는 출처·기간·기기·집계 정의를 기록한다. 광고 키워드 검색량과 쇼핑 검색량은 구분하며 서로 대체하지 않는다. 접근 불가 시 모름으로 유지한다.
- 임의 가중치·종합 SEO 점수로 선택하지 않는다. 검색어별 수요 근거, 상품 조건 충족, 비교 우위/열세, 미확인 사항으로 채택·제외·보류 이유를 설명한다.

표본 수의 고정 목표는 두지 않는다. 범위를 제한해 조사하고 실제 확인한 수와 누락을 보고한다. 구매 의도·상품 적합성·주요 경쟁 조건을 판단할 자료가 확보되면 작성을 진행한다. 반복 조회로 새 근거가 없거나 접근이 막히면 부분 결과와 필요한 자료를 남긴다. 경쟁력이 약하다는 결과도 유효한 조사 결과다.

### 상품 적합성과 등록 방향

공략 검색어군과 채택 이유, 제외한 검색어, 고객의 핵심 질문, 선택받을 이유 및 반대 근거를 작성한다. 검색어군은 여러 표현이 같은 구매 조건을 가리키는 묶음이며 단일 태그 목록이 아니다.

- 실제 규격·기능이 검색 조건에 맞지 않으면 해당 검색어를 제외한다.
- 필요한 사실이 없으면 가설과 확인 과제를 유지한 부분 초안을 만든다. 자료가 없다는 이유로 수요가 없다고 결론내리지 않는다.
- 검토한 검색어에서 적합성이 없거나 선택 이유를 뒷받침할 수 없으면 `상품 재검토` 의견을 낸다. 경쟁력이 검증됐다고 쓰지 않으며 상품명 변경으로 문제를 감추지 않는다.
- 가격·구성·배송의 변경이 필요하면 영향과 대안을 제시한다. 결정 전에는 관련 값을 제안 상태로 둔다. 정보 전달 개선만으로 가격·배송 열세를 상쇄한다고 가정하지 않는다.

### 채널 필드와 콘텐츠 작성

카테고리 후보와 속성을 먼저 확인한 뒤 상품명·태그·옵션·대표 이미지·상세페이지를 함께 작성한다. 선택한 검색 의도와 상품 사실이 각 출력에 연결되어야 한다.

- 상품명·태그의 채택안과 대안 비교는 [조사 절차](workflow.md#조사와-방향-판단)를 따른다. 후보 수요·실제 경쟁 근거와 판단은 [데이터 계약](contract.md#검색과-경쟁)에 연결해 제안서에서 검토할 수 있게 한다.
- 속성·고시·인증은 카테고리별 실제 필드 목록을 확보해 대조한다. 내부 기본 목록만으로 필드 완전성을 선언하지 않는다. 브랜드·제조사·모델·속성은 필요에 맞게 독립 필드로 관리한다.
- 상세페이지는 구매 질문별로 답·근거·중요도·표현 방식·위치를 설계한다. 원본 활용, 요약, 재배치, 근거 있는 설명 추가를 블록별로 선택한다. 원본 유지 여부를 패키지 전체의 작성 제한으로 사용하지 않는다. 표현은 [상세페이지 포맷](../../docs/product-listing-principles.md#상세페이지-포맷)을 적용하고, 내용 구성의 근거와 시각적 참고 출처를 분리한다.
- 대표 이미지와 추가 이미지는 용도·대상 옵션·보여줄 사실을 정한다. 이미지 편집이 필요하면 구체적인 작업 지시와 권한 상태를 남긴다. 제작 지시서와 완성 자산은 구분한다.
- 상세페이지 미리보기는 [등록 자료 작성 절차](workflow.md#등록-자료-작성)에 따라 사진 포함 내부 시안과 게시 준비를 분리해 제공한다. 실제로 확보되지 않은 이미지는 자리표시자로 표시한다. 시안 완성을 게시 승인으로 취급하지 않으며 디자인 설명만 있는 결과를 완성 상세페이지로 보고하지 않는다.
- 고객용 콘텐츠에는 내부 근거 ID·검토 메모·차단 사유·공급처 거래 배너를 넣지 않는다. 필요한 소비자 주의사항과 내부 미확인 사항은 구분한다.

### 검수와 수정

사실·검색 전략·화면·채널 검사를 구분한다. 구조 검사는 참조·누락·버전 불일치를 찾고, 의미 검수는 원문·검색 관측과 출력을 대조한다. 화면은 PC와 모바일에서 실제 글자 가독성·이미지 로딩·잘림·옵션 혼동을 확인한다. 실제 판매자센터에서 수행하지 않은 검사는 미실행으로 남긴다.

반복 오류나 새 근거 없는 수정은 무한 재생성하지 않고 원인·현재 초안·다음 확인을 보고한다. 수정 시 영향받는 검색 판단·필드·콘텐츠를 재검토하며 내용 변경은 새 버전으로 관리하고 이전 승인을 무효화한다. 부분 결과는 유지하되 최신 자료와 혼합해 완성본으로 표시하지 않는다.

## 사용자에게 제공할 결과

관리 데이터에서 같은 버전의 문서·미리보기를 생성한다. 파일 이름과 사용 방법은 [사용법](README.md#사용하기)을 따른다.

| 결과 | 필요한 내용 |
| --- | --- |
| 등록 제안서 | 공략 검색어군·고객 조건·채택/제외 이유·경쟁 비교·선택 이유·불확실성. 첫 화면에서 등록 방향 판단 가능 |
| 등록 입력표 | 채널 필드별 입력값, 해당 옵션, 준비 상태, 필요한 확인. 복사할 값과 내부 메모 분리 |
| 상세페이지 미리보기 | 실제 작성 문구와 이미지 배치. 고객용 화면과 내부 검토 화면 분리, 미완성 자산 표시 |
| 이미지 작업 목록 | 대표/추가/상세 이미지의 채택·편집·추가 확보 작업, 권한과 완료 상태 |
| 확인·검수 보고 | 영향·확인 방법·담당 확인 필요 여부·차단 범위, 수행한 검사와 미실행 검사 |
| 관리 데이터 | 출처부터 검색 판단·사실·필드·블록·자산·검수까지 참조 관계와 버전 |

부분 초안도 위 결과 중 준비된 내용을 제공하고 나머지는 미작성 이유를 표시한다. 문서 분량을 늘리기 위한 자료 전문·경쟁 리뷰 전문의 복제는 하지 않는다.

## 데이터 계약

직렬화는 [listing-2 계약](contract.md)을 따르며 다음 의미를 유지한다. `draft-1`/`mvp-1` 입력은 자동 변환하지 않는다.

| 객체 | 최소 내용과 연결 |
| --- | --- |
| 상품 범위 | 상품 식별, 판매 옵션·구성, 범위의 근거 |
| 출처 | URL/파일, 원문 위치, 확인일, 종류, 적용 범위, 접근 제한; 로컬 자산 해시 |
| 사실 | 값·단위·상품/옵션 범위, 출처 참조, 공급처 표기/자체 확인/충돌/모름 |
| 검색 관측 | 검색어·의도, 관측 환경·표본, 수요 지표 정의, 경쟁 비교와 출처 참조 |
| 등록 전략 | 채택·제외·보류 검색어, 선택 이유·반대 근거, 관측/사실 참조, 판단 상태 |
| 구매 질문 | 질문·중요한 이유·출처 또는 가설, 답을 뒷받침하는 사실·미해결 과제 |
| 등록 필드 | 채널 키·입력값·옵션 범위·필수 여부, 사실/전략/과제 참조, 준비/확인 필요/해당 없음 |
| 콘텐츠 블록 | 위치·문구/이미지·해결할 질문·사실 참조·편집 목적 |
| 자산 | 원본·파생 자산 연결, 권한 범위와 출처, 수정 내용, 사용 위치·옵션 |
| 검수·과제 | 검사 대상·버전·검토자·결과·근거, 과제의 영향·해결 방법·해결 증거 |
| 게시 판단 | 현재 버전, 차단 사유, 사람의 명시적 승인과 대상 버전 |

수치의 확인/추정/모름은 근거 상태와 별도로 보존한다. 미확인 값은 null과 확인 방법으로 표현한다. 제안 문구 안에 들어간 상품 사실도 사실 참조를 가져야 한다. 선택 항목의 미확인은 관련 주장 제외로 처리할 수 있지만 필수 정보는 차단을 유지한다.

## 상태와 게시 판단

다음 상태 축은 서로 독립적이다. 마케팅 가설의 불확실성과 필수 거래 정보 누락을 같은 문제로 취급하지 않는다.

| 축 | 상태와 의미 |
| --- | --- |
| 검색·판매 전략 | 근거 확보 / 가설 검증 필요 / 상품 재검토. 근거 확보도 판매 성과 입증은 아님 |
| 산출물 | 부분 초안 / 검수 대상 완성. 결과 묶음과 필드가 존재한다고 검수 통과는 아님 |
| 게시 검토 | 보류 / 사람 검토 가능 / 해당 버전 승인. 실제 게시와 별개 |

핵심 사실 충돌·필수 입력 누락·권한 미확인·자산 미완성·화면/채널 검수 미실행 또는 실패는 게시 검토를 차단한다. 일부 충돌은 영향받는 주장·필드를 차단하고 나머지 조사·작성은 계속한다. 상품 식별 불가는 전체 상품별 판단을 멈춘다.

검색량이나 차별성의 정량 검증 부족은 별도의 실험 가설로 남길 수 있다. 필수 게시 조건이 충족돼도 `가설 검증 필요` 또는 `상품 재검토` 의견이 있으면 그 근거를 사람에게 제시하고 판매 실험 여부를 결정받는다. 에이전트가 사업 결정을 대신하거나 필수 차단을 승인으로 우회하지 않는다.

사람의 승인은 검토한 버전에만 적용된다. 승인 기록은 신원 인증·전자 서명이나 판매자센터 게시를 뜻하지 않는다. 실제 판매 개시는 별도의 사업 착수 조건을 따른다.

## 검증 계획

아래 사례를 구조·상태 자동 시험과 상품별 의미 검수에 사용한다. 자동 시험·가상 예시 화면의 실행 결과는 [구현 검증 기록](../../records/2026-10-13-listing-agent-implementation.md)에 있다. 실제 상품의 합격 사례와 판매 효과는 별도로 검증하며 상품 선정 표본과 구분한다.

| 시험 상황 | 기대 결과 |
| --- | --- |
| 상품·검색 조건이 맞고 경쟁 자료가 충분함 | 관측부터 검색어 선택·등록 필드·구매 질문·콘텐츠까지 근거 추적 가능 |
| 검색어는 인기 있어도 실제 규격·기능과 다름 | 검색어 제외, 무관 키워드 삽입 없음 |
| 좁은 검색어지만 검색량 자료 없음 | 수요 모름, 낮은 경쟁을 기회로 단정하지 않음 |
| 검색 또는 공급처 접근 실패 | 접근 한계와 추가 자료 명시, 다른 상품 값으로 채우지 않은 부분 초안 |
| 가격·배송 열세로 선택 이유가 불충분함 | 상품 재검토 또는 검증할 가설 제시, 허위 차별점 없음 |
| 원본에 중요 정보가 있으나 읽기 어려움 | 근거를 유지한 요약·재배치와 실제 모바일 가독성 확인 |
| 원본이 이미 충분하고 읽기 쉬움 | 불필요한 추가 문구 없이 채택 가능 |
| 포맷 레퍼런스로 상세페이지 구성 | 공통 포맷 기준에 맞는 미리보기, 대상 상품의 근거·허용 자산만 사용, 작은 화면에서 제목·설명·규격을 읽고 구분할 수 있음 |
| 경쟁 리뷰에만 성능 언급이 있음 | 구매 질문으로만 사용, 우리 상품의 성능 주장에 인용 금지 |
| 공용 이미지·옵션·역할 충돌·권한 미확인 | 영향 범위 식별, 관련 출력·게시 차단, 사실 날조 없음 |
| 변경된 가격·이미지에 이전 검수·승인 존재 | 새 버전과 관련 재검수, 승인 무효화 |
| 자료에 명령문이 있거나 파생본·파일이 다름 | 외부 지시 실행 금지, 불일치 검사 실패 |

합격은 [공통 품질 원칙](../../docs/product-listing-principles.md#조사와-품질-판단)에 따른다. 근거 없는 주장·상품 불일치·미확인 필수값을 평균 점수로 상쇄하지 않는다. 자동 검사는 구조와 상태, 사람 검토는 검색 판단·사실 의미·구매정보 접근성, 실제 채널 검수는 입력·표시 적합성을 확인한다. 모델의 자기평가만으로 전체 합격을 선언하지 않는다.

업무 효과는 자료 조사·준비·검수·수정·수동 입력 시간을 같은 범위의 수동 작업과 비교한다. 시간·비용은 실측하고 목표는 기준 측정 후 정한다. 판매 효과는 [판매 실험](../../docs/execution-plan.md#소규모-검증-흐름)에서 따로 관찰한다. 검색 유입과 구매의 집계 기간·분모를 맞추고, 확보되지 않는 노출 지표는 모름으로 둔다. 전후 변화만으로 콘텐츠의 인과 효과를 확정하지 않는다.

## 구현 검토 범위

실행 구조와 모듈 경계는 [사용법](README.md#구조와-검증-범위), 실제 자료 수집과 작성은 [작업 절차](workflow.md)를 따른다. 로컬 도구가 원문을 자동 수집하거나 상품 의미·검색성과·권한·사용자 신원을 인증하지 않는다. 코드 구현과 개별 상품의 등록 준비 완료는 구분한다.

데이터 소스별 접근 가능성·비용과 실제 채널 표시, 상품별 의미 품질, 업무시간·판매 효과는 실행 시 검증한다. 고정 조사량·성능 목표·유료 서비스는 임의로 확정하지 않는다.
